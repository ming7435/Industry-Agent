# 生产建模、模拟工厂与质量检测接入设计

日期：2026-10-09。版本：1.0。

设计状态：用户已确认接入当前模拟工厂及 Agent 分工；本文为待审阅的书面设计，功能尚未实施。

## 1. 目标与实施范围

将生产建模中的有效设计版本转为当前模拟工厂能够执行的加工程序，保存生产任务及加工结果，在质量检测页面按同一设计版本比较模拟产出尺寸。用户在一个项目内完成设计、下发、加工状态查看和检测，所有记录均可追溯。

首版复用当前工厂的 `virtual-turning-v1` 接口。设备为 `TRAK-TC820LTYSI-001`，支持实心圆柱以及单个同轴贯通圆孔的圆柱。每个生产任务对应一件模拟加工产出；增加产出必须明确创建新任务，不在本版实现批量数量调度。

工厂能力限定为加工区的逐点车削与钻孔仿真，不包含切断、取件、完整刀具碰撞检测和计量设备实测。界面和记录统一标识“模拟生产”“模拟检测”；加工区尺寸符合设计不代表实物产品已经生产或通过制造验收。

本次不扩展通用 CAM、复杂外轮廓、盲孔、偏心孔、倒角、螺纹、齿轮、板材、装配体或 BIM 加工。存在未支持特征时拒绝整个生产方案，不能只加工其中一部分后标记整体完成。不新增 Agent。

## 2. 已核实的基础

当前工厂运行于 `http://127.0.0.1:4529`，生产能力查询返回 `ready=true`、`simulation_only=true`，支持 `cylinder` 与 `coaxial-through-hole`。相关工厂生产测试已执行，62 项通过；该验证证明现有工厂契约可用，不代表项目接入已经完成。

工厂提供能力查询、任务接收、按指令号对账、任务读取和启动接口。接收任务不会启动加工；启动必须携带原程序摘要、操作者和模拟确认。设备异常时任务暂停，恢复设备不会自动恢复任务。运行任务在执行器重启后转为中断，需明确恢复。

CAD Agent 已有本地 FreeCAD 建模入口、Graph、技能工具执行和 Trace。服务端保存完整建模编号、规格、验证结果和文件引用，临时运行缓存有效期为 24 小时。当前没有加工程序生成与生产下发工具。

Backend 已有 MySQL／SQLite 业务记录及事务能力。Quality Agent 的正式质检链拒绝模拟来源，现有比较模块不推测制造公差。当前质量检测页面尚未接入工厂产出。

另有真实质检录入设计及未提交的 CAD、报告、工单改动。本功能保留它们，不同时实施人工录入、CSV、公差标准管理或相关重构。

## 3. 组件职责

**CAD Agent** 承担模拟生产准备与下发。新增专用能力和技能，包含设计资格校验、工艺配置、受限刀路生成、虚拟 NC 后处理、加工区仿真校核、下发及启动。生产动作通过其 Graph／技能工具入口执行，不由页面直接请求工厂，不把任意自然语言或客户端 NC 文本当成可执行程序。

**Agent Orchestrator** 通过现有 Runtime Operations／A2A 架构组织生产与检测，并在服务运行期间持续读取已下发任务的工厂事实。新增明确的模拟生产入口，以任务编号和设计摘要传递已保存事实；生产动作不会进入故障诊断或维修派工链。接收任务与启动任务为两个独立动作，生成模型不触发生产。

**工厂生产适配器** 负责当前回环地址上的契约校验、HTTP 调用和不确定结果对账。复用工厂现有执行器，不修改工厂源码、设备控制接口或执行器的暂停／恢复约束。

**Backend** 保存设计快照、程序包、任务事实、模拟产出及模拟检测记录，负责事务、幂等和身份归属校验。持久事实不依赖浏览器会话或 CAD 临时缓存。

**Quality Agent** 增加独立的模拟尺寸检测分支，调用 Backend 的确定性比较工具并保存模拟检测结果。现有正式质检、整改、复检与放行门禁保持原规则；模拟记录不能通过该分支转换成正式质检证据。

## 4. 数据流

```text
生产建模中的已完成设计版本
  → CAD Agent 校验模型并生成模拟加工方案
  → 用户核对工艺，保存并下发固定程序包
  → 工厂接收任务，返回任务编号与程序摘要
  → 用户启动模拟生产
  → 工厂逐点加工，项目同步真实任务进度
  → Backend 保存完成后的模拟加工尺寸
  → Quality Agent 对照原设计版本执行模拟检测
  → 页面读取保存的检测结果及统计
```

加工完成后自动同步模拟产出，检测仍由质量检测页面的“开始检测”发起。加工状态与检测状态分别保存，任务完成不等于检测通过。

## 5. 模型资格、工艺与程序生成

从服务端读取完整 `FC-…` 编号对应的记录，要求状态已完成、几何验证有效、STEP 回读通过、单实体，且非降级或合成演示模型。客户端只提交完整设计编号，不提交或覆盖规格、标准值、验证结果与设计摘要。

规格单位必须为毫米。首版要求主体为单个圆柱，最多一个同轴圆柱切除且实际交集贯穿主体；识别的是成品孔，不把超出主体的切除工具长度当作成品深度。圆柱支持明确的 x／y／z 轴向与位置，通过保存的坐标变换映射到机床 X 直径坐标、Z 长度坐标。包含其他特征或无法确定变换的模型整体拒绝。

加工表单包含材料、毛坯直径、毛坯长度、夹持长度、刀具编号、径向切深、退让距离、转速、每转进给及工厂契约要求的仿真精度字段；有孔时增加钻头编号与直径。可提供标识为“模拟预设”的初值，用户可以修改并核对。这些预设不作为真实设备工艺推荐。

全部字段按照现有工厂契约验证。毛坯须覆盖目标外径、加工长度和夹持段；钻头直径须匹配目标孔径，车刀与钻头编号不同。尺寸和刀路坐标须在现有六位小数精度下无损表达，超限数据拒绝，不能静默舍入改变设计。

刀路、时间、加工区终态及体积由确定性代码生成与校核，限制点数、数值范围和预计耗时。虚拟 NC 使用工厂认可的固定后处理器，包含 `VIRTUAL ONLY - NOT FOR REAL MACHINE` 标识。页面不允许上传自定义 NC。

工厂的 `setup.tolerance_mm` 仅满足既有仿真契约，本版不把它解释为图纸检验公差。制造公差管理属于真实质检功能。

方案保存后不可变。改变设计版本或工艺会形成新的方案与摘要；已经下发的程序保持原样。存在未应用的设计修改时，页面禁止按草稿下发，要求先生成有效新版本或取消草稿。

## 6. 业务记录与版本追溯

在现有业务记录表内增加 `sim_production_job`、`sim_produced_part`、`sim_quality_check` 三种记录类型，采用独立编号命名空间。所有记录固定 `source=factory-simulation`、`simulation_only=true`，模拟产出保留 `synthetic=true`；禁止写入正式 `production_part` 或 `quality` 记录以规避真实质检门禁。

任务记录包含：项目任务编号、创建人员、批次号、每件产出编号、完整设计编号、名称与展示短号、设计快照及摘要、工艺配置、生成器版本、后处理器版本、固定程序包及摘要、工厂指令号、工厂任务编号、生产状态、同步状态、Trace 编号和服务端时间。

批次号为可明确选择的生产追溯范围；未填写时服务端生成新的模拟批次号。相同批次可通过不同任务生产多件，但统计仍按完整设计版本区分。展示短号不得用于身份查找；每件产出编号由任务身份稳定生成。不得将同一件产出换绑另一个设计或工厂任务。

方案生成时保存完整设计快照，并校验摘要。缓存过期后允许根据已保存方案继续查询、下发及检测；不允许借用旧快照给一个新设计编号生成方案。现有建模历史不迁移、不补造生产记录。

模拟产出保存工厂完成回执、加工区尺寸、单位、程序摘要、工厂事件及同步时间，不把建模参数作为实际产出。首次确认后产出不可变；后续回执与其冲突时进入待复核，不能覆盖原产出。检测记录固定产出摘要、设计摘要和比较规则版本，保存每项比较及操作者；历史检测不随新设计更新而改写。

## 7. 下发、状态同步与恢复

先用事务保存固定方案和指令身份，再对工厂执行下发。相同用户与 `command_id` 对应唯一项目任务；相同参数重试返回同一任务，不同参数返回 409。下发的工厂指令号从保存身份稳定派生，不因网络重试改变。

生产状态包括 `prepared`、`received`、`running`、`paused`、`interrupted`、`completed`。同步状态独立记录 `pending`、`confirmed`、`outcome_unknown`、`unavailable`、`review`，不能用 HTTP 请求成功替代生产成功。

下发超时后先按原指令号查询工厂。找到且程序摘要一致则补全原任务；确定未收到才允许原指令原程序重新下发。对账失败、摘要冲突或返回体不完整时保持结果待核对，不创建替代任务。启动超时只读取原任务核对，不自动重复启动。

启动及恢复必须由当前登录人员明确发起，并携带固定方案身份。操作者由服务端会话解析，客户端不能伪造。调用时要求 `FACTORY_CONTROL_MODE=virtual`、当前工厂地址为回环地址、能力声明与设备／后处理器匹配；不自动启用已停止的设备。

所有线体设备正常且无报警时工厂才允许启动。设备异常、占用或执行器中断按照工厂实际拒绝／暂停原因显示。恢复设备后保留暂停状态，用户使用“继续模拟生产”请求原任务恢复。

生产记录采用独立事务锁和修订号，兼容 MySQL 与 SQLite。网络调用在数据库锁外执行，通过保存的不可变指令和修订号对账；并发提交、同步和检测不得覆盖较新事实。进度与已执行点数不得回退，工厂事件序列须延续此前已确认的前缀，异常返回进入待复核。

同步由 Runtime 后台对账和明确的 POST 刷新入口执行，均只调用工厂读取接口并持久化回执；GET 只读取保存事实。后台对账每两秒检查已下发、运行中及结果未知的任务；不可用时按 5 至 30 秒退避，暂停任务每 30 秒查询。停止追踪已完成且产出已保存的任务，对账不发起接收、启动、设备恢复或重复生产。

后台任务在服务关闭时停止，在服务重启后从 Backend 恢复需要核对的任务。服务在线时即使用户关闭页面，加工完成事实和产出也会继续保存；项目服务离线时工厂继续执行，项目恢复后补齐事实。页面定时读取保存状态，可通过刷新入口主动核对原任务。完成回执与唯一模拟产出在同一事务保存，并发或重试不会增加产出数量。

## 8. 模拟尺寸检测

模拟检测采用 `virtual_profile_dimensions_v1`，范围明确为加工区外径、有效加工长度，以及有孔时的同轴通孔直径。它不宣称检验完整 CAD 形状、材料、外观、装夹、切断或成品长度。CAD 坐标和轴向属于已校验的设计到加工变换，不作为伪造的测量值填入检测行。

标准从固定的服务端 CAD 快照提取。产出值从已完成工厂任务的 `result_profile` 读取并映射，必须与原任务、程序及来源身份匹配，校验有限数、毫米单位、合法外径／内径和加工长度。缺少完成事实或尺寸时不能开始有效检测；客户端不能提交产出值、标准值、通过标志或模拟模式授权。

采用 Decimal 精确比较设计值与模拟加工值，返回标准值、产出值、差值及“一致／不一致”。这是理想仿真参数一致性校验，不使用制造公差判定真实产品合格。结果状态为 `pass`、`fail`、`insufficient_data`、`review`，界面完整名称为“模拟尺寸一致”“模拟尺寸不一致”“数据不足”“待复核”。

Quality Agent 通过新增的可信模拟分支读取 Backend 已保存的产出，调用确定性工具比较，再由 Backend 重算证据并保存。该分支只接受服务端核实的模拟任务身份，不能通过任意请求字段削弱正式质检的来源校验。记录具备设计、程序及产出摘要时，重复检测同一产出复用既有结果。首版不提供编辑模拟产出的入口；出现来源冲突时标记待复核，不复用冲突数据对应的旧通过结论。

现有理想加工通常返回一致尺寸，不通过随机篡改尺寸制造不良率。偏差、缺测和冲突情形通过隔离测试验证，首版不增加缺陷注入功能。

统计范围固定为当前用户可见的完整设计版本、明确批次及模拟来源。按每件产出最新有效检测去重：模拟一致率为一致件数除以有效检测件数，模拟不一致率为不一致件数除以同一分母，覆盖率为有效检测件数除以该范围内已保存产出件数。未完成加工的任务不计为产出，缺测和待复核不计为有效检测；分母为零显示“—”，已有产出未检测时覆盖率可以为 0%。

## 9. 对外接口与工具边界

Agent API 新增 `/api/production/virtual` 前缀，接口均沿用登录会话；写操作额外复用现有写令牌校验。生产记录只对创建人员及已有 `supervisor` 角色可读写，其他用户不能处理他人任务；不增加新的角色体系。

- `GET /capabilities`：核实当前模拟工厂能力与可用性。
- `POST /plans`：提供设计编号、工艺、批次及指令号，生成并保存固定方案。
- `GET /jobs`：分页读取当前可见任务，可按完整设计、批次过滤。
- `GET /jobs/by-command/{command_id}`：读取原指令任务，用于结果未知时对账。
- `GET /jobs/{job_id}`：读取已保存事实、关联产出与检测状态。
- `POST /jobs/{job_id}/submit`：下发保存的程序包，不启动加工。
- `POST /jobs/{job_id}/start`：携带方案摘要并明确启动或恢复原任务。
- `POST /jobs/{job_id}/sync`：核对工厂并保存最新确认事实。
- `POST /parts/{part_id}/inspect`：对保存的模拟产出发起 Quality Agent 检测。
- `GET /quality`：按明确设计和批次读取模拟检测记录及统计。

分页采用稳定任务排序与游标，每页最多 50 条；批次和设计过滤由服务端执行，浏览器不把当前页当作完整批次计算统计。保存方案、下发、启动和检测需校验当前摘要或产出身份；客户端提供完成状态或结论字段一律拒绝。

Monitor Web Server 为上述前缀增加限定代理，转发必要的会话及内部写认证。浏览器不直连工厂，也不从客户端参数选择目标 URL。生产适配器只调用现有能力、接收、查询及启动接口，添加工厂要求的 `X-Factory-Production: virtual-v1` 请求头。

新增 CAD 生产工具和 Quality 模拟检测工具经现有 Tool Registry 注册，通过专用技能限制工具集合。对模型公开的工程查询和建模工具不因此获得启动权限；启动来自明确的页面动作和服务端授权上下文。

## 10. 页面与运行日志

生产建模页面在有效模型结果下增加“模拟生产”面板，展示支持范围、工艺配置、方案、下发和启动动作，以及任务状态、进度和实际错误。未支持模型显示具体原因。切换设计时只读取该版本关联任务，不显示另一版本的旧结果。

质量检测页面增加明确的“模拟检测”来源，沿用零件名称和编号展示，并选择生产任务／产出及批次。“开始检测”发送真实 Agent 请求，显示保存结果、异常参数和三项模拟统计；未产出时显示“等待模拟加工完成”。原真实检测入口及其空数据提示保留，不把模拟尺寸填入人工实测字段。

刷新或重新打开页面从 Backend 恢复任务及产出，不依赖 `sessionStorage` 中是否保留 CAD 历史。会话变化、设计切换和旧异步返回均校验归属；写入期间锁定目标选择，响应未知时保留原指令并引导核对。

所有阶段共用任务／Trace 身份。日志中心新增 `production_simulation` 类型，阶段为“生产准备 → 模拟加工 → 模拟检测”，根据保存事实判断状态；不能套用故障链的监控、诊断、维修方案和派工阶段。加工与检测没有执行时保持对应待执行状态，检测完成后读取正式保存的模拟结果。

本版不增加报告 PDF、经验总结或产品放行动作；已有故障维修报告继续按原业务流程生成。

## 11. 验收要求

完整验收覆盖一次有效圆柱设计和一次带同轴通孔设计的方案生成、下发、明确启动、进度同步、模拟产出保存、页面检测与版本追溯。浏览器刷新及 CAD 缓存过期后，已保存任务仍可继续读取和检测；关闭页面后后台仍保存完成事实，项目服务重启后可补齐离线期间的工厂进度。

必须验证不支持模型、无效／伪造 CAD 记录、未应用修改、工艺超限、刀路／程序／摘要不一致、错误单位、缺失尺寸、伪造通过标志、错设计版本和越权访问均不能产生误导性完成或通过。
