# 取消 Skill 优化的每周份数上限

用户指出不需要额度限制。原先全系统每周三份是用于约束模型调用与审核积压的人为策略，不是平台约束或优化所必需。

## 实现

- 取消候选排序后的前三条截取，所有合格技能保留既有优先级。
- 取消认领阶段的总数上限；每次后台扫描仍只发起一项生成。
- 有完整观测证明的旧周计划升级为选择策略 4，不论此前是否已处理三项，均可补入剩余合格技能。
- 刷新时继续补入后来合格、尚未计划或认领的技能。升级与补入通过 CAS 写入，不覆盖并发认领、候选或失败记录。
- 同一技能在当前周计划中的处理记录用于去重；同一来源不能重放，同一技能跨周也只能存在一份在途稿。失败或结果不确定时不自动重复收费调用。
- 上个完整周、当前版本一致、实际业务问题、支持的测试模式仍是选材条件。缺乏观测覆盖的旧计划不能因升级而重新启用。
- 修改稿仍经人工审核、测试与最终发布才会生效。
- API 的 `limit`、`remaining` 保留为 `null` 表示没有额度；新增全局 `total`、`pending`，`used` 保持为已认领任务数量。按技能过滤仅影响明细，不影响全局计数。
- 页面显示全系统计划总数、已处理、待处理，以及各技能的实际阶段；已处理不表示全部生成成功。
