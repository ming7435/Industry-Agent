# 真实零件尺寸检测：设计说明

日期：2026-10-09。状态：旧方案已被新的数据来源要求替代，不再作为实施依据。

用户随后明确不采用人工录入，并选择接入模拟工厂中的 `RENISHAW-EQUATOR300-001`。新的目标是生产建模提供标准、模拟比对仪自动提供测量样本、系统比较并展示明确标注的模拟检测结果。当前工厂快照只有设备状态，没有逐件尺寸结果；模拟测量接入设计仍待确认。下文人工录入／CSV 的方案仅保留为历史参考，不表示用户批准，也不得按它进入代码实施。

## 1. 用户目标和边界

用户希望“开始检测”真正比较实测值与生产建模参数，返回哪里有问题，以及对应的比例，而不是只改变前端提示。用户目前没有实测记录，已确认先采用人工录入和 CSV 导入，不接摄像头。

本版本提供：

- 保留质量检测标题、左侧任务栏、零件名称选择和设计短号联动。
- 自动读取所选生产建模版本的标准参数；用户只补充实测值、批次和实物追溯信息，并确认缺少的公差。
- 保存真实输入，执行服务端确定性比较，展示异常参数、标准值、实际值、允许范围和偏差。
- 展示尺寸合格率、不良率和检测覆盖率，以及有依据的机器／产线关联和整改建议。
- 数据不足、标准缺失、服务故障时明确说明原因，不默认合格，不产生虚构百分比。

本版本只检验所定义的尺寸和几何特征。尺寸合格不表示材料、外观、寿命或功能已检测，也不自动放行产品、创建维修工单或控制机器。优等品率、返修率、报废率和一次合格率不在本次范围内，因为没有对应分级、处置或初检依据。

## 2. 已检查的现有基础

- `frontend/monitor-react/src/app/App.jsx` 中的 `QualityWorkspace` 目前只读取 CAD 候选记录；“开始检测”仅设置本地状态，没有执行比较。
- `shared/part_design_quality.py` 已有有效 CAD 基准构建、十进制参数比较和证据重算，但当前规则是 `decimal_exact`，不会使用制造公差。
- `services/agent-service/app/api/business_returns.py` 已有建模基准读取、实测输入保存和批次统计读取入口。
- `services/backend-service/app/quality/inspection.py` 已有正式生产零件保存和确定性检验；CAD 模式会固定建模基准，不接受客户端覆盖标准。
- `services/backend-service/app/quality/batch_analysis.py` 已按同批次实物编号去重，重算最新实测记录对应的检测，提供追溯关联和人工核实建议。
- Quality Agent、Backend 质检记录、复检和放行门禁共享证据重算，扩展公差模式必须同步这些消费者。
- 当前安装底板模板有四个圆孔和一个矩形凹槽。现有 CAD 基准不支持该矩形切除，不能直接把刀具参数当成成品尺寸。本版本必须补上这个明确的简单几何场景。

现有 CAD、报告、日志和工单存在其他未提交改动。本功能不回退、清理或一并提交那些改动，也不删除生产数据或缓存。

## 3. 方案选择

已选择：复用现有 Quality Agent 和 Backend 存储／比较链，增加明确的公差模式、录入页面与 CSV 模板。

备选方案是只读取已有实测记录，改动较少，但在目前没有记录的情况下仍无法使用。摄像头测量需要另外定义设备接入、标定、图像算法和测量误差，不纳入本版本。

判断和统计以服务端保存的数据为准。浏览器负责表单、文件解析和展示，不自行把零件判为合格；自然语言模型不决定是否超差。

## 4. 三种身份必须分开

| 字段 | 含义 | 使用规则 |
| --- | --- | --- |
| `design_run_id` | 完整 CAD 版本编号 | 使用完整 `FC-…` 编号关联和校验，不能用五位短号查询 |
| 设计短号 | 页面上的零件编号／型号展示 | 沿用生产建模格式，保留前导零；允许展示碰撞 |
| `part_id` | 一件实物的独立编号 | 每件物料唯一，例如 `B-001-P001`；同一编号复检不增加件数 |
| `batch_id` | 明确的登记批次 | 本次录入／导入必须提供，不能把全库当成一个批次 |

新入口的实物编号和批次号最多 128 个字符。首次保存实物后，绑定的完整设计版本和批次不能静默更换；不同实物、不同版本或不同批次必须使用新的实物编号。页面名称和短号不能绕过上述身份检查。

## 5. 自动读取标准和成品特征

从服务端读取已完成、有效、单实体、已通过 STEP 回读且非演示／降级的 CAD 版本。保存基准快照、完整运行编号和摘要，后续临时 CAD 缓存过期不能改变已绑定的实物基准。

标准提取引入明确的 `parameter_schema_version`。历史记录缺少该字段时按原规则解释、保持原摘要；本次新入口使用 `finished_features_v2`，其基准摘要包含提取版本、完整运行编号和原始规格，避免提取规则变更却沿用旧摘要。

支持现有有可靠参数基准的单零件场景，并新增：

- 轴对齐长方体主体上的互不重叠圆柱孔。
- 长方体顶面开口的轴对齐矩形凹槽／矩形通槽，XY 轮廓完全位于主体内，槽深按切除体与主体的真实交集计算。
- 安装底板模板的主体长宽厚、四孔直径／成品深度／图纸基准位置、凹槽长宽／成品深度／图纸基准位置以及切除特征数量。

对孔与孔、孔与槽、槽与槽的组合，检查真实三维交集；存在交叠、轮廓被改变、封闭内腔、混合添加实体／倒角加工等尚不能可靠转换的情况时拒绝该完整检验基准，说明不支持的特征。不得略过它后声称整件尺寸合格。

标准参数行包含稳定的 `key`、可读名称、单位、名义值和数值／枚举／集合类型。位置按图纸声明的坐标基准解释，不从图像像素或模型包围盒猜测孔位。对于放样、齿轮等已有参数支持，只宣称定义参数的符合性，不宣称所有成品形状已完成计量检验。

## 6. 公差与检验标准版本

本版本不从名义尺寸、零件名称或经验自动推测公差。现有建模规格没有明确公差字段，因此页面提供允许下限／上限，由登录用户根据图纸或检验规程明确录入，并填写依据说明、主动确认。

服务端建立不可变的检验标准快照，保存为 `quality_plan`：

- `plan_id`、`design_run_id`、`design_digest`、`parameter_schema_version`。
- `comparison_rule = tolerance_inclusive_v1`。
- 每个连续数值参数的 `min`、`max` 和单位；离散数量、枚举和边集合采用明确的一致性规则。
- 依据说明、确认人员、服务端确认时间、规范化后的 `plan_digest`。
- `state = incomplete | confirmed`，由服务端校验规则完整性并判断；客户端不能自称 confirmed。

数值范围必须有限、上下限齐全、下限不大于上限，且包含名义值；单位必须与参数一致。显式的相等上下限表示零公差，不能因没有填公差而自动采用零公差。数量参数必须为整数，按数量一致性判断；枚举与边集合按有效值比较，不套用连续公差。

允许保存不完整的标准以及无标准的真实观测，以便显示偏差；但它们不能产生整件尺寸合格结论。只有明确确认、完整且摘要正确的标准可以用于最终合格／不合格分类。修改允许范围会产生新的标准版本，不能重写历史检测。

## 7. 真实输入与观察版本

人工录入区包含批次、实物编号、可选机器／产线编号和测量时间。标准参数自动列出且只读，实测输入默认全部为空，禁止“用标准值填充实测值”。

保存观测时，由服务端解析身份并固定：设计基准、所选标准版本或缺少标准标记、输入来源、测量时间、录入时间和当前登录人员。每次明确更新实测值或采用新标准都形成新的 `quality_observation`；历史观察和检测保持不变，`production_part` 指向当前观察。

更新已有实物必须携带 `expected_observation_id`，并让用户确认“保存新的观测”；版本已变化则返回 409。修改公差后不会自动把旧实测绑定到新标准。要按新标准判断，需要用户重新确认实测记录并保存新观察，原测量时间和新录入时间分开保存。

机器／产线是用户录入的生产追溯信息，不是系统自动发现的故障根因。对已有设备目录能核实的编号校验真实名称，不伪造名称或线路映射；未知目录来源的追溯信息标记为“人工提供、未核实”。缺少信息时正常检测尺寸，但显示“无法定位机器／产线”。

## 8. CSV 导入

提供根据当前完整设计版本和标准生成的 UTF-8 CSV 模板，一行对应一个实物的一项参数。模板的实测值和实物编号为空，不包含预填的合格样本。

列为：

```text
batch_id,part_id,design_run_id,plan_id,parameter_key,parameter_name,actual,unit,device_id,line_id,measured_at
```

- 版本、参数键、参数名称和单位自动填入；标准缺失时 `plan_id` 为空。
- 同一文件只导入一个设计版本、一个批次和同一个标准版本，避免混用比较依据。
- 用户填写每件实物编号、实测值和测量时间，可重复模板参数组以增加实物。
- 同一实物的追溯信息和测量时间必须一致；重复的“实物编号＋参数键”是错误，不采用最后一行覆盖。
- 空实测值允许保存为缺测，不转换成 0；非空非法数、未知参数、错误单位、错设计版本、错标准和伪造结论字段必须拒绝。
- 枚举和边集合采用参数声明的格式，模板说明列出合法值。表格文本按数据显示，不执行公式或 HTML。
- 第一版上限为每文件 2 MiB、10,000 个数据行、50 件实物，每件最多 512 项；超过时给出明确提示，要求拆分文件。
- 浏览器解析支持 BOM、CRLF、引号、逗号转义和引号内换行，提供行号错误和导入预览；此时不写入业务记录。
- 用户确认导入后提交规范化对象，服务端再校验。整组测量保存采用事务：身份冲突或任一无效行导致全部回滚，返回具体实物／参数错误。
- 首版导入仅创建新的实物记录；对已存在编号返回冲突，要求在单件录入页面明确保存新观察，避免文件意外覆盖。

## 9. “开始检测”的真实流程

```text
选定设计、批次和当前实物观察
  → 服务端核对身份、基准、标准及观察版本
  → Quality Agent 调用 Backend 的确定性参数比较
  → 校验返回证据并保存质检记录
  → 按同一统计范围读取批次比例和问题关联
```

新比较规则：

- 实测为空：该项待检测，没有偏差数值。
- 有实测但公差／确认标准缺失：可以显示“实测－名义值”的偏差，该项待判定，不能用精确相等冒充公差合格。
- 标准有效且实测在闭区间 `[min, max]` 内：该项合格，边界值包含在内。
- 标准有效且实测在范围外：该项超差，返回相对名义值的偏差，以及到最近允许边界的超差量。
- 任一必检项缺测或无法判定：整件为数据不足／待判定；已经确认的超差项仍展示，不被缺测项遮盖。
- 全部必检项都可判定：任一项超差则尺寸不合格，否则尺寸合格。
- 几何基准、返回体、摘要、来源或观察版本不可信：待复核，不沿用缓存结论。

实现时在共享比较模块增加显式公差分支；历史无新模式标记的记录保留 `decimal_exact`。Backend 检验、Agent 校验、保存证据、批次重算和复检／放行证据重算使用同一规则及同一标准快照，禁止只修改前端判断。

## 10. 接口与幂等设计

现有接口保留兼容行为，新 UI 使用明确的新入口，以免旧运行中的服务忽略字段后仍按旧规则检测。

| 新入口 | 职责 |
| --- | --- |
| `GET /api/quality/workspace/{design_run_id}?batch_id=...` | 返回新能力声明、可靠设计基准、标准版本、该设计／批次的登记实物和最新可核实结果；有界读取，每页最多 50 件 |
| `POST /api/quality/workspace/{design_run_id}/plans` | 核对服务端名义值，保存人工确认的不可变标准版本 |
| `POST /api/quality/workspace/{design_run_id}/measurements` | 保存单件新观察，或事务性创建最多 50 件导入记录；客户端不能提交 passed、标准名义值或人员身份 |
| `POST /api/quality/parts/{part_id}/inspect` | 仅依据已保存观察执行 Quality Agent；必须携带请求编号和期望观察、设计及标准摘要 |
| `GET /api/quality/inspections/{request_id}` | 读取当前登录用户该次请求的真实执行／保存状态，用于网络中断后对账 |

上述入口均校验真实团队会话；写操作同时保留既有内部写令牌边界。记录人员来自服务端会话，不相信请求中的姓名或角色。不新增不存在的管理员账号或质检角色，也不改变已有设备控制权限。

新业务记录使用现有正式 Repository，新增 `quality_plan`、`quality_observation`、`quality_submission` 类型；复用 `production_part` 和 `quality`，不要求删除旧表或旧数据。SQLite 与 MySQL 都必须覆盖事务、唯一身份和冲突行为。

保存和检测请求携带稳定 `request_id`，服务端保存请求指纹和处理状态。同用户相同请求编号、相同内容返回原结果；相同编号不同内容返回 409。质检保存另外以“实物＋观察版本＋设计摘要＋标准摘要＋规则版本”去重，并发重复检测不能创建第二份正式结论。

导入后的批次检测在浏览器按用户选定的当前页实物顺序执行单件入口，一次只保留一个检测写请求，逐件显示进度。每件保存结果都是独立的真实事实；不因为后续一件失败而声称此前结果未保存。换页继续检测需明确点击，不偷偷检测全库或其他批次。

网络中断后的写操作标为“结果待确认”，只通过读取入口对账，不自动重试写入。若发现已保存结果则展示；明确未开始时可以再次提交；仍在处理或状态不确定时保持待确认。离开页面不能宣称取消了已经送出的服务端写操作。

新的尺寸检测入口不自动生成 PDF 或调用 Report Agent。现有其他质量流程的报告行为不改变，也不自动执行 Release／Close。

## 11. 统计口径

新页面明确显示统计范围：所选完整设计版本＋批次＋公差规则＋所选标准版本。不同标准、历史精确比较与本次公差检测不混合计算。

按实物编号去重，每件只采用与当前保存观察、设计和标准完全匹配的最新有效检测。新实测已经保存但尚未复检的实物回到待检测，不能继续借用旧合格结果。

| 展示指标 | 计算 |
| --- | --- |
| 尺寸合格率（良品率） | 合格件数 ÷ 已完成有效尺寸检测件数 × 100% |
| 尺寸不良率 | 不合格件数 ÷ 同一有效检测件数 × 100% |
| 检测覆盖率 | 已完成有效尺寸检测件数 ÷ 此统计范围内登记实物件数 × 100% |

有效检测件数为所有必检项均可判定的合格件与不合格件之和。缺测、缺标准、证据不可信和请求未确认的实物不进入合格／不合格分母。已发现超差但其他必检项缺测的实物单列“已发现异常、待补齐”，保留问题关联，不混入完成检测比例。

有效检测件数为 0 时合格率／不良率为 null，页面显示“—”；没有登记实物时覆盖率也是“—”。已有登记实物但未完成任何有效检测时，覆盖率可以真实显示 0%。统计只表示已登记范围，不冒充全批次实际产量或抽样推算。百分比四舍五入到两位小数，件数与计算口径同时可查看。

批次读取失败不撤销已保存的单件结果；单件结果照常显示，比例标为“暂不可用”，只允许刷新读取。

## 12. 页面与错误状态

保持当前页面风格，不恢复之前删除的大型历史列表。依次展示：

1. 标题与检测零件：名称选择、设计短号。
2. 检验标准：自动参数、允许范围、依据说明和主动确认；默认可折叠。
3. 实测输入：人工录入／CSV 导入切换，批次、实物追溯、标准只读及空白实测字段，明确保存按钮。
4. 开始检测：针对已保存的当前单件或当前页批次实物，展示真实进度。
5. 检测结果：尺寸合格／尺寸不合格／待检测／数据不足／待复核，三项比例，异常与未判定项；合格项可以折叠查看。

每项异常列出可读特征名、允许范围、实测值、偏差和超差量。机器／产线关联有保存来源时展示编号、可核实名称、关联件和建议；缺少时明确无法定位。全部结果标明仅为尺寸／已定义几何特征检测。

服务端保存数据才是持久事实。浏览器不把观测、标准、结果或批次凭证写入 CAD 会话；切换零件清空未保存输入和旧结果，未保存草稿切换前要求确认。异步返回按完整设计、批次、标准、实物及当前读取请求校验归属，旧返回不能覆盖新选择。保存／检测期间禁止修改作用域；身份变化清除私有结果。

身份失效、基准不支持、观测冲突、服务断开分别显示实际原因。无模型和加载中禁用检测；没有实测记录时保留待检测，不写一条“失败检测”来冒充实测失败。明确存在保存的缺测观察时，检测可返回数据不足，但不会增加有效检测数。

## 13. 机器、产线和解决建议

复用现有批次分析中的追溯和安全建议。关联表示某件异常实物的记录指向该机器／产线，不等于已经证明机器发生故障。当前设备报警即使能读取，也只是附加的当前状态，不自动作为生产时根因。

建议按具体尺寸、孔位或漏加工特征分类：保存异常证据、复核量具／单位／基准，再由工艺人员核对刀具、程序和装夹，整改后复测。材料问题或外观问题不能从尺寸偏差推断。建议只用于人工核查，不控制设备、自动改加工参数或自动派工。

## 14. 验收与兼容要求

代码实施按测试先行，至少验证：

- 页面完整设计版本选择、设计短号前导零、碰撞隔离和未保存草稿切换保护。
- 自动标准取自服务端，篡改名义值、比较规则、确认人或通过标志不能生效。
- 安装底板四孔和矩形槽成品参数、超长刀具交集深度；相交切除和不支持模型拒绝。
- 公差边界、非对称范围、显式零公差、缺少公差、缺测、NaN、无穷值、错误单位、数量与枚举规则。
- 有超差又有缺测时，异常可见但不算已完成有效检测；没有任何实测时不默认合格。
- CSV BOM、引号、换行、重复参数、错版本／错批次、大小限制、事务回滚和既有实物冲突。
- 单件合格／不合格保存与读取，首次保存、更新、复检去重、并发版本冲突和网络未知结果对账。
- Agent 与 Backend 重新计算使用同一标准快照；伪造证据不能通过保存／复检／放行门禁。
- 新规则与历史 `decimal_exact`、历史五类质量检测相互隔离，旧记录不迁移、不改判。
- 不同比较依据不混算；0 分母为 null；已登记未检测覆盖率为 0；跨页／批次不偷偷扩大检测范围。
- 机器／产线缺失或未核实时不编造归属、名称或根因；没有设备控制和自动派工请求。
- 浏览器真实点击确实发送检测请求并读取正式保存结果，不再只改变本地提示；慢返回、切换、登录变化和统计失败无误导结论。
- 前端完整单元测试、相关后端／Agent 契约和浏览器回归、构建及真实页面视觉检查；明确报告实际未运行和失败的范围，不将测试样本写入生产数据。

已有其他工作区改动必须原样保留。服务重新加载需要先核对运行任务，不能为了启用新接口直接中断其他正在执行的项目任务。
