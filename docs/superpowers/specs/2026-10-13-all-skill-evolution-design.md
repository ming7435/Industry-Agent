# 全技能独立优化循环

## 目标

当前九类 Agent 的全部已注册 Skill 均可参与观测、候选生成、人工审核、验证与发布。用户要求连续实施，不再按文件要求确认。Skill Loop 不等于执行业务的 Agent Loop。

## 原有与新增路径

诊断使用 machine_flow，检索使用 knowledge_flow，建模使用 cad_spec_flow。其余路由、维修、派工、质检、报告、记忆、CAD 查询与虚拟生产技能使用 review_flow：优化基于实际输入输出的核查与信息关注规则，不修改固定算法、阈值、状态机、审批、人员资格、公差或设备控制权限。

review_flow 不是整条业务链、实体内核或生产验收。模型只能选择服务器枚举出的非敏感事实路径及确实为空的缺项路径；输出事实值由服务器复制，不允许模型返回数值、工具调用、自由代码或 passed=true。候选测试需与人工预期路径匹配，并确认基线、依赖和只读边界。

## 运行接入

共用 trace_skill_node 的结果边界读取本次冻结的 Skill。仅已发布自动候选正文包含追加规则时启用核查，初始固定流程不增加付费调用。每个 Agent 结果至多一个有界模型请求，包含本轮待核查的已发布技能。独立线程池最多两次并行核查，不排队；模型超时上限八秒，饱和或输出不合格明确记为尚未验证。通过后以独立日志事件返回重点事实和缺项；网页将它放在所属 Agent 的核查区，原业务 Result、成功失败状态与实际副作用保持不变。

Agent 没有调用此边界或未使用指定技能时，不补造执行记录。原来的专用验证与正文消费不替换为通用核查。所有技能的主业务成功率仍按真实业务回执计算，核查完成不得被算成维修/派工/质检成功。

## 数据与权限

全局每周最多三份候选，持续覆盖、当前指纹、服务器实际问题记录、并发 CAS 和人审发布不变。老计划保留已占额度及全部候选，仅补空位；无记录/纯基础设施失败不优化。四项北极星按技能归属统计，新核查验收明确标记模式，不能冒充机器全流程验收。

输入输出按 JSON 有界处理、凭据及权限上下文在冻结前排除。专家测试样例含敏感字段时在持久化前拒绝；未知句柄不能转换成字符串。候选正文完整送入模型，不用日志截断器裁剪；单文档两万四千字、合计四万八千字超限明确拒绝。异常不重试工具，不影响已经完成的业务操作；核查不可用明确记录未验证。测试使用临时技能目录、隔离存储及模型替身，不触发真实设备、付费模型或生产数据库。不改源码 Skill 正文、不覆盖并发用户修改。

专家中心默认展示全部技能。review_flow 显示测试输入、已执行结果、预期重点和预期缺项，而不是故障触发选项。旧 machine-test 入口也拒绝非诊断模式，整机回执不能替代核查样例验收。
