# FreeCAD 生产建模统一工作台：总体路线与第一阶段设计

日期：2026-10-11。状态：用户已确认“中文 AI＋手动 CAD 编辑”、原生内核接入及分期顺序，并在书面方案交付后回复“开发”，现进入第一阶段实施计划编写；尚未开始功能实现。本文不是实施计划，也不表示全部 FreeCAD 功能已经接通。

## 1. 用户意图与成功标准

生产建模成为 FreeCAD 的统一操作入口：用户既能用中文描述设计，也能查看模型树、选择对象、修改参数和使用 CAD 工具。两种操作作用于同一份真实文档，不能只新增示例按钮、静态预览或独立演示。

用户确认的第一阶段是模型树、对象选择、属性和尺寸修改、三维视图，以及修改后刷新、保存新版本、重新打开和质检标准更新。失败应保留上一个有效版本。后续按工作台逐项实现和验收，不将第一阶段称为“全功能完成”。

版本衔接必须保留现有需求：零件名称和五位设计短号联动；生产建模产生的零件可以在质量检测中展示；新版本可重新检测；旧结果不能显示成新版本的结果。设计值仍是标准参数，不是实际测量值；本设计不改变现有检测数据来源或生产放行规则。

本设计采用的工程约束是：复用本机 FreeCAD、已有服务和账号会话；保持当前左侧导航和质检页面；不自动安装插件、执行用户提供的 Python、操作真实设备或改变外部模拟工厂。这些是实现边界，不是缩减长期功能目标。

## 2. 已核实的基础与缺口

以下是截至本次设计时的本地代码和文件证据，不代表实时能力验收：

- 本机程序为 L:/industry_agent/.runtime/freecad/bin/FreeCAD.exe；rpc-ready.json 记录版本 1.1.4、构建 20260928、提交 4fd3bf320d9566a27e60069fc8387448aaa3a094。该文件是启动证据，不代替每次请求的健康检查。
- ProductionCadWorkspace.jsx 已有中文建模、结构化规格、参数修改、运行轮询和文件下载；工程图、部分装配、BIM 和钣金已有受限适配器，不是整个工作台的网页实现。
- FreeCadModelViewer.jsx 主要读取 STL 和运动数据。整体 STL 预览不能直接提供可靠的原生对象、面、边编辑身份。
- modeling_api.py 提供状态、创建运行、读取运行和固定文件下载接口。FreeCADRunStore 在 Redis 中保存运行，期限为 86400 秒；浏览器 sessionStorage/localStorage 是历史索引，不是持久文档库。
- freecad_mcp.py 从白名单结构化规格生成可信脚本，验证实体及 STEP 回读。当前部分形体被合成为 PartDesign::Feature，不能据此宣称已有完整 Sketcher／PartDesign 特征历史。生成后会关闭本次文档。
- FreeCADClient 只允许内部调用 execute_code 和 get_rpc_status；网页没有任意代码接口。执行超时可能为 outcome_unknown，现有“不盲目重放”原则应继续保留。
- 账号会话解析已存在于 app/api/team_auth.py；服务 API 令牌不等于个人身份。新文档必须有明确的会话归属，而不是凭浏览器传入的用户名称授权。

核实的 Mod 目录包含 Part、PartDesign、Sketcher、Draft、Assembly、TechDraw、SheetMetal、BIM、Fem、CAM、Surface、Mesh、MeshPart、Points、ReverseEngineering、OpenSCAD、Inspection、Measure、Spreadsheet、Material、Robot、Plot、Import、Idf、AddonManager、Help、Start、Test、Tux、Web、Show、FreeCADMCP。目录存在只表示安装内容；是否注册命令、依赖是否就绪、网页是否可执行必须分别验证。

## 3. 接入方式与分期

选择“原生 FreeCAD 内核＋网页操作界面＋共同的受控命令层”。它使 AI、手动操作和持久文档一致，保留可验证几何和版本关系；代价是各工作台需要各自的交互与适配验证。

未选择的两条路线：远程显示完整桌面可直接利用原有 GUI，但需要独立的显示、输入和会话隔离，不等于网页原生编辑；只增加 AI 模板更容易扩充，但不能满足完整手动操作目标。本阶段不混入远程桌面子系统。

总体路线如下，只有第一行是本文的详细实施范围，其余阶段分别形成后续设计与计划：

| 阶段 | 交付范围 | 对前阶段的依赖 |
| --- | --- | --- |
| 1：文档编辑基础 | 能力目录、真实对象树、对象级选择、基础形体及规格参数编辑、版本保存、质检衔接 | 现有原生执行器、账号和存储 |
| 2：参数化设计 | Sketcher 几何与约束、PartDesign 特征历史、拉伸／切除／旋转／扫掠，以及撤销／重做 | 文档、稳定对象身份、命令事务 |
| 3：几何与数据工具 | 完整 Part／Draft／Surface，Measure／Inspection，Spreadsheet／Material，Mesh／MeshPart／Points／ReverseEngineering／OpenSCAD，以及扩展导入导出 | 选择映射、类型化属性和受控文件处理 |
| 4：专业建模与制图 | Assembly、TechDraw、SheetMetal、BIM 的完整交互；现有受限能力继续保留 | 草图、特征引用、对象与子元素身份 |
| 5：分析与制造 | FEM 求解、CAM 工艺与刀路、Robot 轨迹、Plot 和相关专业数据 | 模型版本、所需求解器和后处理器的能力验证 |
| 6：配套与扩展 | 工作台剩余命令、Import／Idf 专用交换、帮助和首选项等配套；宏与 AddonManager 作为独立受权限约束的管理模块 | 逐命令覆盖审计、独立依赖与权限设计 |

“全部功能”的验收口径是锁定版本和安装模块的命令／交互清单逐项有对应实现、依赖状态和测试证据。不能用完成若干工作台名称或注册按钮替代覆盖审计。目录中辅助模块要说明用途，不能全部假定为独立工作台；新安装插件或升级 FreeCAD 后重新生成覆盖清单，不自动继承旧版本的验证结论。

CAM 生成代码不等于控制机床，Robot 轨迹不等于实际运动指令，FEM 安装目录不等于求解器可运行。宏、扩展安装、任意文件访问和实际设备控制不因“全功能”目标而自动获得权限，也不能用永久禁用这些能力冒充全量验收。

## 4. 第一阶段范围

### 4.1 文档和页面

保留生产建模入口、现有中文需求和已有建模能力，增加模型树、属性面板、文档状态及保存版本入口。三维区支持对象级选中高亮、旋转、平移、缩放、适应视图、正交／透视和标准方向视图。零件名称与设计短号在文档及质检展示中保持联动。

支持三种文档起点：新建空文档；由本阶段中文／结构化规格生成文档；对现有服务端已完成且验证有效的建模记录明确创建可编辑副本。原记录及原产物不覆盖。缺失、过期或校验失败的旧记录说明原因，不能凭浏览器缓存重造标准。

所有生产建模文档的原生对象都进入模型树，包括组、组件和非几何对象；有形体的对象进入三维场景。无法编辑的类型仍展示，属性标明只读原因。不能因未实现某工作台的编辑器而把整个零件隐藏。

第一阶段只开放下面的真实修改，其他类型不提供虚假的通用属性写入：

- 创建 Part::Box、Part::Cylinder、Part::Sphere、Part::Cone，编辑各自的原生尺寸属性。
- 修改受适配支持的对象位置与旋转、显示名称和可见性；复杂装配／BIM 受约束位置只读，不能绕开其依赖关系直接移动。
- 对已有可信结构化规格使用当前 validate_spec 支持的字段修改和重新生成；保持目前的形体、绘图、装配、BIM、钣金范围及校验，不静默忽略不支持的字段。
- 显式整模型重新生成属于新工作修订，必须标明对象被替换并清除失效选择；它不是原生特征历史编辑。

基础形体命令的尺寸名统一为：box 的 length、width、height；cylinder 的 diameter、length；sphere 的 diameter；cone 的 bottom_diameter、top_diameter、height。适配器将直径转换为原生半径属性，不能把半径直接当直径展示。首版仅生成完整基础形体；圆锥顶径可为 0，其他尺寸为正，圆锥底径大于顶径。尺寸修改针对已有类型的这些字段，不开放局部角度裁切等其他原生属性。位置为三维毫米向量，旋转为非零轴向量和有限角度值，服务端归一化旋转后保存。

文档零件名称在创建／首次生成时确定；set_label 只修改对象 Label，不能把某个孔或组的标签覆盖成质检零件名称。直接创建的基础形体最多 24 个；旧规格生成继续使用原有数量限制。第一阶段不隐式融合这些形体。

本阶段不提供任意外部 FCStd 上传执行、任意脚本／表达式、插件安装、交互式草图约束、面／边级造型命令、完整撤销重做或专业求解器配置。受控导入在本阶段仅指服务端可信已完成版本的副本；通用文件导入由后续阶段单独设计。

### 4.2 AI 和手动操作

手动表单及中文 AI 都提交同一组类型化命令。AI 负责把需求转成命令和参数，不负责生成可直接执行的 Python。新增文档命令纳入当前工具白名单；既有规格生成复用原校验和可信脚本适配器。

AI 命令缺少对象、尺寸或单位时要求补充，不猜测并执行。修改需先显示对象和参数变更，用户确认后提交；用户已明确提交的原有生成流程保持原有交互。AI 不可用时，手动基础建模、编辑、保存和重新打开仍可用。

## 5. 组件与依赖

| 组件 | 单一职责 | 使用的输入／输出 |
| --- | --- | --- |
| 能力目录 | 合并安装信息、运行时命令、网页适配和验证证据 | 只读目录，不执行建模 |
| 文档 API 与命令服务 | 校验会话、类型化参数、修订和幂等；调度执行 | 文档快照、命令状态 |
| 原生适配器与统一执行协调器 | 在 GUI 线程执行受控读取／修改和几何校验 | 服务端托管 FCStd 与候选产物 |
| 文档持久库 | 保存归属、修订、命令和发布版本的关系 | Backend MySQL；受控产物文件 |
| 网页文档状态与查看器 | 同步模型树、选择、属性、网格及命令进度 | 带文档／修订身份的快照 |
| 已发布版本与质检桥接 | 提供不可变标准和版本更新通知 | 完整 FC 运行身份，不提供测量值 |

Frontend 复用 production-cad 下的工作区及视图基础，独立抽出文档状态、命令调用、树和属性编辑组件，避免继续把所有行为塞入一个大组件。Agent Service 增加专用文档／命令模块，既有 modeling_api.py 保留兼容读取；Backend 增加独立 CAD 存储模块，不挪用质检批次或工单记录。

执行链路：AI 或手动输入 → 命令校验及持久认领 → 隔离候选文档 → 原生重算与校验 → 工作修订快照 → 页面同步。明确保存版本后，再发布不可变标准给质检。

## 6. 身份、状态与持久性

新文档使用服务端生成的 DOC-UUID，拥有一个会话解析得到的 owner_user_id。工作 revision 是递增整数，从空文档 0 开始；成功修改推进修订，失败不推进。发布 version 单独从 1 递增，绑定当时的工作修订，不与操作次数混用。

每个原生对象有服务端分配的 object_id，并与文档中的 FreeCAD Name 映射。显示名称是 Label，不作查找或权限键；对象替换分配新 object_id，不能在删除后重用旧身份。Name 和 Label 的区别依据[FreeCAD 官方对象命名说明](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Object_name.md)。

五位 part_number 仅用于展示，保留前导零，不作数据库唯一键。新建输入只接受五位十进制数字或留空；复制旧版本时继承其显示短号；新文档未填写时由服务端从文档身份派生并保存，后续版本保持这一显示编号。不同文档可能短号相同，仍通过 DOC、revision 和完整 FC 运行身份区分。

Backend MySQL 新增 cad_documents、cad_revisions、cad_commands、cad_published_versions 独立记录。在线持久性不依赖 Redis TTL 或浏览器；SQLite 仅用于隔离测试。每个修订保存服务端受控的原生快照及摘要，发布记录保存完整规格／标准来源、校验和产物清单。仅工作头及发布头指针可变，历史修订和发布内容不可覆盖。

托管产物位于项目 output/freecad-documents 下的服务端生成文档／命令子目录，不接受客户端路径。候选文件写完后校验摘要，再由短数据库事务登记和切换工作头；网络调用和 CAD 执行不在数据库锁内进行。目录中的未登记候选不作为有效修订，不能自动清理可能仍在执行的命令文件。

空文档允许保存工作状态，但没有有效实体时不能发布为检测标准。工作修订与发布修订不相等时显示“有未发布修改”；刷新或重启可以恢复最后一次已提交的工作修订，未提交的输入不能宣称已保存。

## 7. 命令契约、执行和错误处理

修改命令包含 command_id、document_id、expected_revision、明确的 command_type 和严格参数。归属从会话获取，不接受请求体自报权限；目标对象必须属于该文档与修订。单位首版统一为毫米和度，有限数值、正尺寸（圆锥顶径的 0 例外除外）及现有 ±10000 mm 资源边界继续适用。

command_type 首版限定为 create_primitive、set_primitive_dimensions、set_placement、set_label、set_visibility、replace_from_spec；发布为独立命令。每种命令只允许明确字段，禁止任意属性名、Python、Gui.runCommand 字符串、文件路径和不受控表达式。replace_from_spec 使用完整 validate_spec 校验，不削弱原有操作数及工作台限制。

幂等键由 owner_user_id 与 command_id 构成；指纹绑定文档、目标修订、类型和规范化参数。重复同一请求返回原状态，同一身份换参数返回 409。expected_revision 已过期同样返回 409 并要求重新读取，不自动把修改套到新版。文档同时只能有一个未终结写命令，数据库认领后才开始 CAD 操作。

工作命令状态为 accepted、running、completed、failed、outcome_unknown。新执行器和原有建模执行器共用同一原生执行协调器，串行运行 GUI 写任务；不能各自仅持有一个进程内锁就宣称跨工作进程互斥。首版采用单一执行进程和数据库活动命令租约；多 API 进程仍向该进程提交。租约超时不表示原生任务已停止，必须按收据核对后再恢复写入。

执行前，从已提交修订的托管快照创建唯一候选文档；可信脚本原子认领本次执行，抵御底层重发；以明确文档句柄操作，不依赖 App.ActiveDocument。只有项目管理的 FreeCAD 实例和本次创建的文档可被协调器操作和关闭，不扫描、改写或关闭其他桌面文档。

修改后重算，检查对象错误状态、实体合法性、数量和有限几何数值，保存候选 FCStd 和带修订身份的对象／网格快照。候选验证成功才推进工作头。失败只丢弃未提交候选的有效性，最后有效修订及发布版本不变。

命令失去响应时保留 outcome_unknown，不自动再次创建、修改或发布。原生执行端保存认领与完成收据，包含命令指纹、候选摘要和验证结果。恢复只核对收据并完成尚未登记的提交，不重跑未知动作；收据缺失且无法确认执行终结时阻止后续原生写入，提示核查原任务。

FreeCAD 离线、存储不可用、登录失效、版本冲突、非法参数和几何失败分别展示具体原因，不能一律显示“建模完成”，也不能退回虚构模型。日志保留命令身份、阶段和错误类别，不输出令牌或完整敏感环境。

## 8. 快照、对象选择与实时更新

快照包含 document_id、revision、published_version、对象列表、对象属性的类型／单位／可编辑性、依赖关系、验证状态和逐对象网格清单。模型树与网格使用同一个 object_id 映射；非几何对象只进入树，不制造虚假形体。

逐对象网格保持同一 CAD 坐标系，通过统一 Z 向上到查看器坐标变换呈现，不能分别居中导致组件位置错误。点选网格取得 object_id，再选中树节点和属性面板；显示／隐藏及高亮不改变模型标准。网格没有面／边来源映射时不得把三角形序号冒充 Face／Edge。

第一阶段的选择停在对象级。后续子元素操作必须增加带修订的 B-rep 映射和引用校验；不能保证形状修改后边编号不变。该约束依据[FreeCAD 官方拓扑命名说明](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Topological_naming_problem.md)，不是通过保留旧序号解决。

命令完成后，同一页面立即重新读取快照。可见页面每 2 秒只读检查当前工作头及发布目录版本；后台页面暂停轮询，重新获得焦点或可见性时立即刷新。同源同标签页事件及 storage 事件用于提前通知，但服务端记录始终是权威来源。

每次请求绑定账号、document_id、revision 和前端请求世代；切换文档、退出登录或收到更新时取消旧请求，丢弃身份不符的响应。新版网格与树一起替换，过期选中对象清空；不能先换名称、仍显示旧模型或旧属性。

“实时”指提交成功后的刷新及跨页面发现更新，不指每个未提交键入都触发 CAD，也不承诺求解耗时小于 2 秒。UI 保留命令阶段和当前有效修订，未收到成功证据不先显示新尺寸已经生效。

## 9. 保存版本与质量检测衔接

“保存版本”针对指定 expected_revision，使用独立幂等 command_id。重新核验模型，生成固定允许的 FCStd、STEP、STL 及已有规格要求的绘图／运动产物；STEP 回读、实体数量、体积和边界等继续沿用当前验证标准。校验全部通过后，原子写发布记录和更新发布头，生成完整 FC-64位十六进制身份。

同一工作修订已经发布时，再次保存返回原发布版本，不因刷新或更换命令身份创建重复版本。发布范围由快照的 product_root_ids 决定：规格生成适配器记录其最终产品／组件，直接创建的基础形体分别作为产品根；不导出构造几何及中间特征，也不按当前可见性改变范围。多个产品根导出为保留组件身份的组合体，沿用对应的实体数和干涉校验，不自动融合成一个零件。

发布版本的文档身份、修订、规格、参数来源和产物摘要不可变。基础原生形体提取明确尺寸；可信规格模型保留完整规格和已有标准提取结果；未知特征标为未覆盖，不能用包围盒声称已检查全部孔槽、制造公差或装配关系。

增加服务端 standard_parameters 契约，包含提取模式版本、稳定参数键、object_id、名义值、单位、局部坐标／位置方向、来源属性和未覆盖项。摘要绑定 DOC、revision、FC 发布身份、完整提取结果及提取器版本。现有规格沿用原标准提取；原生基础形体走明确的新适配器，不能把任意旋转或原生属性硬塞入旧的轴对齐规格。质检标准入口显式支持该契约；未知类型保留未覆盖信息，不绕过完整性判断。spec 对可信规格版本保留原结构；原生文档没有对应旧规格时为空，标准读取不得仅因 spec 为空拒绝整个零件展示。

所有新发布版本的质检消费优先读取 standard_parameters，不回退到可能已过时的源 spec。编辑改变了源规格和最终几何的对应关系时，适配器必须更新可证明的映射；无法证明的参数标记未覆盖，不能原样继承为当前标准。set_placement 首版仅对四种独立原生基础形体开放；旧规格模型的位置通过受校验的规格修改和重新生成处理。

兼容读取 get_freecad_run_record 及现有 runs／artifacts 路径：新增持久发布版本先按登录归属读取，返回当前消费者需要的 run_id、status、spec、validation、artifacts、part_name、part_number，并补充 document_id、revision、version、standard_parameters。明确不存在于持久目录的旧身份才进入原有临时读取；持久库错误或权限错误不能回退绕过。新发布的 run_id 不随 Redis 过期失效。

现有无个人归属的旧建模记录继续采用原有只读访问规则，不批量认领给当前用户。创建副本必须由登录用户明确发起，并核验该请求按现行规则可读的服务端记录及托管产物。新文档访问、修改及产物下载均检查个人归属。新界面产生的模型由受保护文档命令记录归属，不从浏览器历史推断。

质量检测零件目录合并当前用户的持久发布版本与原有可验证来源，并保留名称、短号、版本显示。生产建模产生的复杂零件也能展示；缺少标准或测量覆盖时说明哪些项未覆盖，不凭空给合格率。

发布通知沿用 completedDesigns.mjs 的同页／跨标签页机制，并增加服务端目录版本检查。质量检测处于“跟随当前建模”模式时跟随新的已发布版本；用户明确选择历史版本时保持选择，同时提示可用新版，不强制覆盖。发布后下一次目录检查即可更新，正常网络下可见页面的发现目标为一个 2 秒轮询周期加一次请求时间。

选中版本发生变化时立刻清除旧批次在当前结果区的展示与进行中的检测响应。旧批次在服务端仍绑定旧 run_id 和基准摘要；用户可按原版本查回，但不得改绑或跨版本计算比例。新版本只有发起新检测并获得相符数据后才展示结果，不能拿新版设计值重算旧观测后冒充新测量。

保存、刷新和读取标准都不触发检测、生产放行、工厂启动／停止或机器维修。保留当前质量检测页面，不恢复之前删除的“工厂产出检测／比对仪数值演示”切换按钮。

## 10. 接口轮廓与权限

以下是拟新增接口，不是现有接口能力声明，统一位于 /api/cad/freecad 下：

| 入口 | 契约 |
| --- | --- |
| GET /capabilities | 读取内核版本、模块、原生命令和网页适配状态；不建模 |
| GET /documents | 当前会话可访问的持久文档目录，游标分页 |
| POST /documents | 以幂等创建身份建立空文档或可信旧版本副本 |
| GET /documents/{document_id} | 当前已提交工作头、发布头与命令状态 |
| GET /documents/{document_id}/snapshots/{revision} | 读取指定工作修订的完整快照 |
| POST /documents/{document_id}/commands | 提交类型化修改，202 返回命令身份 |
| GET /documents/{document_id}/commands/{command_id} | 查回命令状态及已提交结果，不重放 |
| POST /documents/{document_id}/publish | 发布指定修订，202 返回幂等发布命令 |
| GET /designs | 当前会话的不可变已发布版本目录，包含目录版本及游标 |

修订网格通过归属校验后的托管产物接口下载，文件名称／格式由清单确定，不拼接任意路径。发布版本保留现有固定文件下载形态。SVG／PDF 保留内容类型、nosniff 和 CSP sandbox 防护；外部链接不作为托管文件证据。

新个人文档路由在已有服务令牌基础上解析 maintenance_session；同源浏览器写入保留 Origin 检查，代理必须转发会话而不是相信 actor_id 请求字段。生产环境缺少认证配置时拒绝服务，开发环境的服务令牌豁免不豁免个人文档归属。首版不引入文档协作角色或跨账号共享。

## 11. 能力目录与真实覆盖

每项能力包含 capability_id、模块／工作台、原生命令身份、内核版本指纹、参数模式版本、installed、discovered、dependency_ready、web_adapter、manual_verified、ai_verified、disabled_reason 和证据引用。读目录不调用付费模型、不启动求解器、不更改设计文档。

各字段相互独立：发现原生命令并不开放任意执行；安装了模块并不将 dependency_ready 自动设为 true；有手动表单并不意味着 AI 路径通过。可用入口必须有适配器、依赖就绪和对应路径的验证证据。纯视图／帮助类命令没有 AI 参数模式时明确标记不适用，不伪造 AI 验证。

能力页按“已验证可用／已接入待验证／待接入／缺少依赖／当前版本不支持／受权限约束”展示，并给出原因。第一阶段只将本文列明并实际验收的能力标成可用；其他工作台仍显示真实状态。已发现但未适配的命令不能从前端直传给 Gui.runCommand。

FreeCAD 的多工作台及文件交换范围参考[官方功能说明](https://freecad.github.io/Website/features/)。本项目的覆盖状态必须以本机验证为准，不能直接复制官网介绍作为实现证据。

## 12. 第一阶段验收与回归

验收必须有真实本机 FreeCAD 测试，不只依赖 Mock、按钮截图或模型缓存。测试使用独立临时文档／目录，不能修改现有用户文档和外部工厂。

1. 手动新建基础形体，树、视图、原生类型及尺寸一致；修改尺寸和位置后重算，网格、属性、体积证据均更新；保存、关闭及服务重启后从 FCStd 恢复同一修订。
2. 中文生成和后续手动编辑使用同一 DOC 身份；AI 修改经确认后走相同命令契约。模型服务不可用时手动路径仍通过；AI 路径未经实际模型调用验证时不得标为已验证，也不自动消耗付费额度。
3. 对现有可信复杂模型创建副本；模型和全部对象可展示，未适配属性有明确只读原因；原发布记录、几何及产物摘要保持不变。
4. 保存两个不同修订，完整 FC 身份和版本关系可查，短号保留前导零；模拟短号碰撞不会串文档或批次。持久版本不依赖 Redis 临时记录，清除临时缓存后仍能按授权读取。
5. 同页和双标签页更新：跟随当前建模时发现新的已发布标准；历史版本选择不被强制更换；延迟返回的旧快照和检测响应不覆盖新版。
6. 质检针对新版本可以发起新的检测，标准从服务端不可变发布记录读取，旧批次及摘要不被改写；没有实际或现有明确来源的检测数据时不伪造结果。
7. 同一命令重复提交仅执行一次；改变参数或过期修订返回 409；不同账号的读取、修改、命令查回及产物下载均不可串用。伪造 Label、短号、actor_id、对象身份和路径不绕过检查。
8. 原生修改失败、STEP 校验失败、数据库提交失败、网络断开和 GUI 超时均不替换最后有效工作头／发布头。终结收据可恢复提交；未知任务未确认终结前不会重放或启动并发写任务。
9. 文档切换、空文档、无几何对象、离线、会话过期和网格损坏均有明确 UI；资源界限和旧工作台校验不被放宽。
10. 现有 FreeCAD API／可信规格、装配、BIM、钣金、工程图，以及质量零件联动、检测结果身份和后台代理回归不退化。工厂和工单控制请求在本阶段验收中应为零。

自动化分为类型化契约和幂等单测、数据库／执行协调集成测、原生内核验证、浏览器交互与跨标签页回归。具体任务顺序和测试命令写入下一步实施计划，不在本文件假定它们已通过。
