# 模拟工厂 Equator 300 自动检测：设计说明

日期：2026-10-09。状态：自动检测方向已在会话中确认；本文等待用户审核，尚未进入产品代码实施。

## 1. 用户要完成什么

质量检测页面选择生产建模中已完成的零件，名称与设计短号联动；点击“开始检测”，自动取得该建模版本的标准参数和模拟比对仪的测量样本，比较后返回问题项、对应数值、比例、可追溯的机器／产线和核查建议。用户不重新填写标准尺寸，也不逐项人工录入实测值。

数据来源已明确为模拟工厂的 `RENISHAW-EQUATOR300-001`，不是实体仪器、工业摄像头或文件导入。全部结果显著标注“模拟检测”，不能用于真实生产放行。

本文替代旧的 `2026-10-09-real-quality-inspection-design.md` 人工录入／CSV 方案。下文提出的适配层、模拟比较规则和样本数量是本次书面审阅内容，不表示功能已经实现。

## 2. 现有基础与缺口

- `QualityWorkspace` 已有标题、零件选择、设计短号、开始按钮和待检测区域；按钮目前只设置本地提示，没有执行检测请求。
- 建模版本保存在服务端 FreeCAD 临时记录中，包含完整 `FC-…` 编号、规格和实体／STEP 校验。前端历史索引不能代替服务端规格；未保存的编辑参数不作为标准。
- 当前工厂 `GET /api/snapshot?device_id=RENISHAW-EQUATOR300-001` 可读取运行状态、测头、电源、环境等，但没有每件零件的尺寸测量结果。
- 现有共享比较规则为 `decimal_exact`，正式质检和放行校验会拒绝模拟证据。这些正式门禁必须保留。
- 安装底板模板已经提供主体、四孔及矩形凹槽参数；现有标准提取不能处理该矩形切除，需在本次模拟检测的独立提取规则中支持，不能拿切除刀具的完整尺寸冒充成品尺寸。

## 3. 接入方式和范围

采用本项目内的模拟比对仪适配层：读取外部模拟工厂的设备状态作为模拟工位是否可用的依据，再由明确标注的数值模拟器生成逐件尺寸样本。这不是外部工厂已经返回的原生计量结果，也不是物理探针或三维扫描算法。

另一种方式是直接修改外部模拟工厂、增加计量结果接口，会同时涉及另一个服务的代码和部署；不作为本次默认实施方式。本次不修改外部工厂，不向它发送启动、停止、移动测头、改刀补或故障注入命令。

不恢复已删除的大型历史列表，不新增人工测量表单、CSV、摄像头、PDF 报告、维修派工、自动放行或真实制造公差设置。名称、短号和尺寸标准始终来自所选生产建模版本。

## 4. 组件与职责

1. Agent Service 的独立模拟检测路由：校验登录及写权限，读取服务端 CAD 版本和模拟工厂快照，向 Backend 提交可信来源包；不调用大模型或重新建模。
2. 独立共享模块 `shared/simulated_part_design_quality.py`：提取模拟标准、生成可复现样本、十进制逐项比较、计算统计。不得改变旧的正式 `decimal_exact` 及放行规则。
3. Backend 的独立模拟检测服务／内部路由：校验来源包、原子保存批次及请求、重算读取结果、处理重复提交。复用正式 Repository 的存储能力，但使用独立记录类型。
4. 前端模拟检测状态模块：提交明确的检测请求、读取保存结果、处理身份和选择变化。比较、比例与问题归属不能仅由浏览器自行声明。

执行链路：已保存的建模版本 → 模拟工位状态校验 → 数值模拟器生成逐件样本 → 确定性比较 → 原子保存 → 页面展示。

## 5. 标准提取与身份

完整 `design_run_id` 是查询和隔离依据；页面五位设计短号仅作展示，允许短号碰撞，不能作为批次或实物唯一键。

首次检测只接受服务端已完成、校验有效、单实体、STEP 回读通过且不是降级或模拟建模结果的版本。建立 `simulation_parameters_v1` 基准快照，摘要包含完整版本号、原规格、提取版本及提取结果，禁止客户端提交或覆盖名义尺寸。沿用单零件最多 24 个几何操作的限制，提取结果最多 512 项；有限数值、明确单位、合法方向及数量是必要条件。

首版明确支持单个长方体／圆柱体，以及长方体主体上的轴对齐圆孔、顶面开口矩形凹槽／通槽组合，必须覆盖安装底板模板。孔深、槽深按切除体与主体的交集提取；位置遵守设计坐标基准。提取主体尺寸、孔／槽尺寸、位置、方向和特征数量，保存稳定参数键与单位。

检查切除之间的真实三维交叠和轮廓改变。添加多个主体、相交切除、封闭内腔、与倒角／圆角组合、建筑、装配及其他未支持模型返回“不支持完整模拟尺寸检测”，保留待检测，不跳过特征后声称整件合格。

读取界面当前及最多 20 个历史候选版本，沿用现有短号格式和前导零。另合并当前用户最多 20 个已保存模拟基准，允许曾检测的版本在临时 CAD 缓存到期后仍被选择。持久目录只能来自已验证的模拟基准；不能把浏览器草稿补写成基准。

每批使用服务端生成的 `SIM-BATCH-…` 编号，批内每件样本有独立 `SIM-PART-…` 编号。批次固定绑定完整设计、基准摘要、比较规则及模拟器版本，不能跨零件或跨版本混算。持久记录键采用有命名空间的固定哈希，长度不超过现有 MySQL 的 128 字符限制。

## 6. 比较规则：不擅自增加制造公差

首版模式明确为 `nominal_exact_demo_v1`，页面显示“模拟设计一致性检测”。它回答模拟样本的已定义参数是否与模型一致，不回答真实加工允许误差是否合格。

- 连续数值按有限十进制比较；一致为该项“与设计值一致”，不一致为“与设计值不一致”，返回名义值、模拟测量值、单位和差值。
- 方向与特征数量按各自的合法值和精确一致性比较，不能混用连续尺寸单位。
- 缺测为待检测；无效数、错误单位、未知参数或损坏摘要为待复核，不转换成 0 或通过。
- 所有必检参数可判定且一致，整件为“模拟一致性合格”；完整但存在不一致，整件为“模拟一致性不合格”。任一项缺测或不可判定则整件待判定，已知不一致仍展示。

不默认设置 ±0.05 mm，不把未提供的公差解释成真实生产零公差。页面必须说明“未定义制造公差；本结果仅表示模拟参数与设计值的一致性”。未来接入真实仪器和制造公差是另一个明确范围。

## 7. 模拟样本如何产生

每次新的检测请求生成 10 件数值模拟样本，数量不是工厂真实产量。种子由固定模拟器版本、请求身份、设计摘要派生；同一请求回放得到相同样本，刷新页面不会重新随机生成结果。

模拟器使用名义参数及独立偏差模型生成样本，并记录对应场景：参数一致、某项尺寸／位置偏离、某项缺测。场景和偏移选择由稳定种子决定，不直接返回预设合格率。尺寸偏移保证数值有限、单位明确；数量及方向采用各自的离散场景。完全一致的样本属于明确的测试场景，不能标成实际测量。该生成器模拟的是数值观测，不声称已经扫描模型、移动测头或使外部工厂执行了测量程序。

每件保存参数观测、场景编号、模拟器版本及测量生成时间。返回统一标记 `simulation=true`、`synthetic=true`、`source=local-simulated-equator-adapter`。工厂状态快照另存为工位状态依据，不能把电压、测头偏折量、健康度或环境温度换算成工件尺寸。

## 8. 模拟工位门禁与故障状态

Agent 与 Backend 都要求显式启用 `QUALITY_SIMULATION_ENABLED=true` 且 `FACTORY_CONTROL_MODE=virtual`；生产环境不提供生成入口。页面读取能力声明，不用固定文案假定后端支持新功能。

生成前从配置的工厂地址只读请求指定设备的快照，设置 5 秒超时和 2 MiB 响应上限，严格核对设备编号、类型及时间。快照时间距服务端现在最多 30 秒，未来偏差最多 5 秒；没有时间或过旧则拒绝生成。

必要条件为设备及控制状态运行、无报警，且上电、通信、测头在位、急停释放信号为 1，测头故障和保持信号为 0。必要信号缺失、非有限数或布尔冒充数值时拒绝；校准到期剩余小时缺失或非正时同样拒绝。运行及指标读取匹配设备的 `monitor`，控制状态读取匹配设备的 `detail`；两块身份、状态相互矛盾时拒绝，不取第一台设备作为回退。`idle` 可以表示模拟工位待测，不需要发送启动命令。

这些条件只是本项目模拟器的可用性规则，不是实体设备安全认证或计量标定证明。离线、故障、停止、超时或错误设备返回具体待检测原因，不产生一批“不合格零件”冒充测量失败，不回退到断线随机数。

## 9. 保存、幂等与读回校验

使用独立 `simulated_quality_basis`、`simulated_quality_batch`、`simulated_quality_request` 记录，不创建或覆盖正式 `production_part`、`quality`、报告、放行或工单记录。所有模拟保存及读取仍保留模拟标记。

请求身份由服务端登录用户和浏览器生成的 `request_id` 共同确定，指纹绑定完整设计；首次成功时固定规则、模拟器、样本数和基准摘要。相同用户、相同请求、相同设计返回原批次；同一请求改为另一设计返回 409。不同用户不能读取或复用他人的请求、基准目录或批次。

Backend 新增专用于模拟请求的短事务，SQLite 使用写事务；MySQL 锁定该请求在独立命名空间中的唯一键。计算和保存 10 件有限样本、请求与新基准在同一事务完成，失败全部回滚，不提交可见空记录。先锁请求键、再锁基准键，采用固定次序；同一用户同一完整版本的基准不可变，不同请求并发使用相同基准时核对同一摘要，摘要变化拒绝，不能用保存覆盖旧标准。数据库锁内不进行网络调用，不借用锁正式质检记录的旧 MySQL 事务保护模拟并发。

已完成请求的查回优先于 CAD 和工厂重新读取，即使设备随后离线或临时 CAD 到期，也可以取回原结果；新请求仍需要新的工位状态。只有临时 CAD 读取明确返回 404 时，才能回退到该用户此前保存且摘要核实的完整版本；Redis 故障、身份冲突或当前基准不一致不能用历史快照掩盖。

读取时核对用户、设计、基准、模拟器和规则，重新按观测计算结论与比例；模拟种子及场景应能重现观测。保存结果与重算不一致则待复核，比例为空。不能通过更改 `passed`、来源或模拟标记把记录转换成正式检验。

## 10. 接口边界

Agent Service 的新命名空间为 `/api/quality/simulation`：

| 入口 | 职责 |
| --- | --- |
| `GET /capabilities` | 读取启用状态、设备、样本数、规则及模拟范围，不生成观测 |
| `GET /designs` | 返回当前用户已保存的模拟基准目录，最多 20 项，不冒充全部 CAD 历史 |
| `GET /designs/{design_run_id}` | 读取所选服务端标准或该用户已验证的持久快照，以及该版本最新模拟批次；不保存新基准 |
| `POST /detect` | 仅接收完整设计号和 1—128 字符、匹配 `^[A-Za-z0-9_-]+$` 的 `request_id`；拒绝额外字段，取得可信来源后执行并保存一批模拟检测 |
| `GET /requests/{request_id}` | 当前用户对账并读取已保存结果；未查到只表示尚未查到，不保证另一写请求未执行 |

这些入口校验现有团队会话；生成入口同时使用既有写认证。人员身份来自服务端，客户端不能指定用户、测量值、标准值、来源、生产追溯、通过标志或比例。Backend 对应独立 `/internal/quality/simulation` 路由使用既有内部令牌，并校验 Agent 传入的来源包。

缺失登录返回 401，关闭或非模拟环境返回明确不可用原因，基准或工位不适用返回 409，格式错误返回 422，来源读取失败或存储失败返回 502／503。写入后的网络中断标为“结果待确认”，先用读取入口对账，不自动提交新的请求身份。用户明确重试时只能复用原请求身份，由事务幂等处理。

## 11. 统计和优良率含义

页面保留用户所需的比例位置，但加模拟及一致性限定：

- 模拟合格率（设计一致性）＝完整且一致的样本数 ÷ 全部完整、可判定样本数 × 100%。
- 模拟不良率（设计不一致）＝完整且不一致的样本数 ÷ 同一可判定样本数 × 100%。
- 模拟检测覆盖率＝完整、可判定样本数 ÷ 本次保存样本总数 × 100%。

待判定样本不进入合格／不合格分母；已发现不一致但其他参数缺测的样本仍保留问题，单列待判定。没有有效样本时两项质量比例为 null，显示“—”；有 10 件但全部待判定时覆盖率可以真实显示 0%。

每个比例伴随分子、分母和本次批次号，按件统计而不是按参数个数统计。只展示当前批次，不累计重复点击、页面刷新或其他版本；百分比四舍五入到两位。比如 7 件一致、2 件不一致、1 件待判定应算 77.78%、22.22%、90%，这是验算示例，不是接口固定返回值。没有优等品等级依据，不另报“优等品率”。

## 12. 机器／产线定位和解决建议

`measurement_device_id` 固定指向比对仪，`production_device_id` 另指向有模拟生产追溯的加工机器；两者不能互相代替。仅因检测到偏差，不得把 Equator 认定为加工故障机器。

默认演示配置明确声明一条虚拟路线：`TRAK-TC820LTYSI-001` 加工 → `ELITE-CS612-ROBOT-001` 转运 → `RENISHAW-EQUATOR300-001` 检测，演示产线编号为 `SIM-LINE-A`，显示名为“模拟 A 线”。这条路线属于本项目的模拟场景设定，不声称外部工厂已经登记了该件物料的真实加工履历。

核对快照设备目录中的加工机器身份和名称后，才给样本绑定该演示追溯；保存 `traceability_source=simulation_profile`，页面标注“模拟生产关联”。没有有效配置或设备不匹配时显示机器／产线“未知”，不随机指认设备，也不把三维页面上的 A 线展示标签猜成真实生产追溯。

关联结果按异常样本聚合，显示具体参数、设计值、模拟测量值、差值、关联机器／产线以及 `root_cause_status=unconfirmed`。整改建议按尺寸、位置、数量等分类，包含核对测量基准、加工程序、刀具、装夹、工序及复测步骤，明确只是核查建议。模拟场景不是实际故障根因，不生成真实维修任务或执行机器控制。

## 13. 页面行为

保留左侧任务栏、质量检测标题、名称选择和设计短号。新增紧凑的模拟设备／规则说明及只读标准参数摘要，不新增人工输入测量值。

点击开始按钮应真正请求上述生成入口，显示“正在模拟检测”，成功后显示本次模拟合格／不合格／存在待判定样本的状态、比例、样本件数和问题明细。每项问题有具体数值；未知机器／产线明确显示未知。没有问题时只能说“本次已完成样本未发现设计参数不一致”，不能说整批真实产品无缺陷。

按钮在无有效标准、正在读取、没有模拟能力或已有提交时禁用；未登录时明确提示使用现有登录入口。提交期间禁止更换零件。身份变化、切换版本或读取请求更新后，旧异步结果不能覆盖新页面。

保存结果取自 Backend，浏览器不把模拟记录写入 CAD 会话，不修改生产建模当前运行。刷新只读回保存结果；用户再次点击产生新的明确模拟批次。未知写结果保留对账状态，不把浏览器取消请求说成已撤销服务端执行。

## 14. 验收要求

- 实际点击发送检测请求，读取服务端建模标准；修改浏览器的名义值、来源、通过标志或比例不生效。
- 安装底板长宽厚、四孔、矩形凹槽及位置正确，超长切除刀具深度取交集；不支持或交叠模型明确拒绝。
- 模拟值来自可复现生成器，不使用设备健康度冒充工件质量，也不在工厂断线时仍生成样本。
- 一致、不一致、缺测、非有限数、错误单位、损坏摘要、未知参数及 0 分母均有测试；已知异常和缺测同时存在时不能算完整不合格件。
- 设计短号前导零、短号碰撞、完整版本隔离、临时缓存到期后持久基准回读、不同用户隔离均有测试。
- 同请求重复点击、并发创建、相同编号不同设计、保存失败回滚、网络未知结果对账与读回重算一致性均有测试；SQLite／MySQL 专用事务语义都验证。
- 仪器离线、停止、故障、校准到期、缺少信号、错误身份、过旧时间和 API 不支持显示真实原因，不出现默认合格率。
- 模拟记录不进入真实统计、报告、工单或放行。原正式质检、复检、放行及模拟证据拒绝回归必须保持。
- 机器／产线缺少追溯不编造；计量设备与加工设备分开；整个功能不调用工厂控制接口。
