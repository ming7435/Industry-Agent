# MySQL / Redis 存储与维修方案删除设计

## 用户目标

维修方案列表提供单条及批量删除；日常服务不再使用 SQLite 保存数据。临时存储使用 Redis，长期结构化记录使用 MySQL，向量检索继续使用现有 Milvus。按照用户此前“不再反复询问”的要求直接实施，不新增 Agent、不改变业务门禁。

## 存储边界

- MySQL：事件结果及完整审计、方案列表投影与删除标记、审批状态与幂等认领、工单、质检、报告、学习结果、设备安全待办、文档及分块正文。
- Redis：短期记忆及短期缓存，明确 TTL；缓存失败不能伪造成功，缓存过期不能重复执行业务写入。
- Milvus：现有向量与索引。不把关系型状态迁移到向量数据库，不改变模型或集合。
- PDF、STEP、STL 等文件仍在现有文件目录保存，元数据使用长期存储；不将大文件强塞进 Redis。
- 旧 SQLite 只保留隔离测试适配器与只读迁移入口；开发/生产在线入口不得暗中回退 SQLite。MySQL 未配置或不可用时明确失败。

## 删除语义

使用软删除，保留原事件、审计日志和关联工单，不重新执行或释放原事件的幂等状态。单条及批量删除必须由服务器验证登录身份和服务令牌；允许已登录小组成员管理方案列表，但不能因此修改工单、派工或控制设备。批量数量最多 100 个，先验证全部 ID 存在，再原子写删除标记，避免部分误删。重复删除幂等。

列表 API 返回 deleted_plan_ids，前端合并工单快照及实时监控快照时也过滤这些 ID，刷新和重启后不能重新出现。删除按钮有确认提示；未登录时不显示可执行的删除操作。

## 兼容与迁移

新 MySQL JSON 记录使用压缩长期正文和独立列表投影，避免页面加载完整大日志。每次操作独立数据库会话，耗时 Agent/模型调用不占数据库事务。写入未知结果不盲目重试，审批继续原子 CAS。

迁移读取旧库时使用只读连接，逐记录写入 MySQL，不覆盖已有不一致数据；记录计数、摘要和迁移进度，允许中断恢复。旧库不删除，新旧事件不能自动同时处理。默认先 dry-run，实际迁移显式执行，不擅自重启服务。

配置仅调整本地存储相关白名单值和启动默认值，不输出、备份或改变密钥。源码修改前逐文件备份。新增连接、存储、删除、迁移测试先复现失败再实现；各服务独立进程测试，联调使用独立 MySQL 测试库和 Redis 随机命名空间，不触发模型收费或机器控制。
