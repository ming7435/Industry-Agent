# CAD 三维建模节点设计

## 用户要求与范围

用户要求将已有三维建模接入 CAD Agent 的真实节点：节点调用 Skill，Skill 调度 Tool。沿用用户此前“后面不需要再问”的连续实施要求，直接修改当前本地项目，不建立远程任务、不覆盖已有修改、不改前端布局。

## 调用链

`原建模 API → 原有界任务队列 → CAD Agent 图 prepare → model_3d → production_modeling_skill → generate_3d_model → 原需求解析、CadQuery 实体生成、校验和导出 → finish`。

- 在原 CAD 图中只增加 `model_3d` 一个节点；原工程查询分支继续运行。
- Skill 为中文 Markdown，结构化工具步骤实际决定调用哪个工具，不仅用于写日志。
- 复用 ToolRegistry 的工具权限校验和输入输出日志；建模工具是内部本地工具，不暴露给其他模型，不允许任意请求指定本地文件或建模服务对象。
- 队列工作线程绑定可信的任务和输入；上下文使用任务级作用域隔离，不能跨任务调用。
- 原上传、版本、幂等、人工确认、文件摘要校验、预览和下载契约保持不变。
- 不运行真实设备控制，不修改模型配置或数据库，不新增收费模型探测。

## 验收

测试必须真实运行 API、CAD 图、Markdown Skill 调度和 ToolRegistry。真实实体生成通过现有隔离 CadQuery 子进程验证；尺寸不足、未确认参数、内核失败不能变成成功。日志能关联同一任务的 Agent、节点、Skill、工具、输入和输出。原图纸查询不能获得建模工具权限。
