# 日志页反复重新加载修复（2026-10-07）

用户要求日志页不要每次返回都重新刷新。原因是 App 切页会卸载 LogsWorkspace，丢失运行列表、选择、筛选和明细；每五秒的后台索引更新也显示“刷新中”，详情变化时还会先清空旧数据并卸载展开内容。

## 修改

- 首次访问后在当前应用会话内保留日志页及其 DOM，切页仅隐藏，保留运行选择、筛选及原生详情展开状态。离页暂停轮询并取消尚未完成的日志请求。
- 返回立即显示已读日志。最近五秒内成功读取过的索引不因切页重复请求；过期索引在后台更新，不清空内容或反复显示刷新按钮忙状态。
- 详情使用运行编号、Trace 集合、事件数量、最新事件时间、状态及错误数量判断变化。同版本无需重复下载；“刷新运行记录”会主动刷新索引和当前详情。
- 同一运行只允许一个详情请求在途。索引持续增长时允许慢请求完成并显示，再补取最新版本；避免每五秒取消请求导致首次内容一直无法出现。切换运行或离页仍取消并拒绝旧响应。
- 更新失败保留旧明细并显示提示。原始事件使用真实 `trace_record_id` 作为稳定标识，新增事件不使原有展开内容折叠或错位。

缓存仅在当前应用内存中，不持久化日志到浏览器存储。完整重载网页仍需首次读取。日志的新内容继续在后台同步，手动刷新按钮保留。此次只修改前端日志页，不变更后台业务、工单派发、设备或 CAD 环境。
