# FreeCAD MCP 网页工作区

2026-10-12。本次是完整目录、白色工作区与受控规格任务的扩展，不是全部 FreeCAD 功能的网页移植验收。用户曾要求回退，随后明确要求继续修改；没有执行回退，远程和 HEAD 未改变。

## 用户要求与当前边界

目标是前端保留 FreeCAD 全部建模功能，通过 MCP 调用真正的内核，不嵌入桌面窗口。本次把原生发现清单扩展为工作台和命令资源目录，并调整网页布局、增加已有规格工作流的参数入口；并未把未实现的草图、特征历史、FEM、CAM 等功能标记为可执行。

白色工作区提供菜单栏、工作台筛选、命令搜索、左侧模型树与属性、中央真实 WebGL 模型、右侧建模任务。现有基础形体、尺寸／位置／显示／标签编辑、中文提案和发布流程继续使用既有文档接口；改动不引入 iframe、窗口捕获、桌面事件转发或浏览器 Python 执行入口。

## 简化日常入口（用户后续反馈）

## 原生目录如何读取

- `GET /api/cad/freecad/catalog`：保留全部已发现的命令及已安装工作台；不截成固定几个示例。命令未注册时，需要读取相应工作台，不能凭安装目录编造命令。
- `POST /api/cad/freecad/catalog/discover`：登录及同源验证后，以账号和 request_id 绑定幂等的持久发现任务；浏览器只提交工作台标识，不提交 Python。
- 原有单 worker 通过标准 stdio MCP `execute_code` 工具执行服务端固定发现模板；任务与其他建模作业共享执行队列。读取指定工作台会初始化原生 GUI 工作台，不执行用户选择的建模命令；结束时恢复原工作台。
- 原生激活返回失败、工作台身份不一致或恢复失败时写失败收据，不报告完成。超时保持未知结果，不自动重复执行；网页可查回原任务。
- `GET /api/cad/freecad/catalog/jobs/{job_id}`：按任务创建账号授权，只查询原收据。其他账号不能查询该发现任务。
- 目录与版本、进程 PID 和启动时间绑定。旧进程目录仍可查看，但不能派生当前执行入口。通用命令等分组不是原生工作台，其刷新不向 FreeCAD 发送虚构的工作台名称。

目录中四个基础形体命令能打开已有参数表单，确认后才提交既有受控文档命令；圆角与倒角打开明确标示的“全部边、受控规格重建”任务，不直接运行 GUI 命令。点击或搜索目录本身不执行建模。未适配命令可查看原生说明和快捷键，但没有执行按钮。目录数量不等于网页已实现功能数量。刷新目录后，选中命令从最新记录读取接入状态，不沿用旧执行入口；未打开文档时可读取目录，但不能打开修改入口。

## 同一文档内的规格任务

右侧“规格与工作台建模”及“零件／工作台”菜单复用现有 `replace_from_spec` 适配器，提供当前规格编辑、通孔、全部边圆角／倒角、工程图／剖面，以及齿轮、圆形截面放样、法兰、底板、钣金、转动关节装配和 BIM 的现有受控模板。参数用中文表单编辑，不需要输入 Python，浏览器不提供原生脚本入口。

当前模型任务必须有可信 `source_spec`，或者单个、独立、未旋转、完整定义的原生基础形体。位置、旋转和圆形主体角度缺失，或者对象类型／依赖／范围不能证明时，拒绝转换，不用包围盒或默认原点猜测几何。新规格模板会替换整个工作文档的对象，不自动保留旧对象或把专业功能与原模型混合。

草稿绑定 DOC 和准备时的工作修订。用户核对参数后勾选确认才能提交；参数变化清除确认；新修订出现时旧草稿不能执行，必须重新读取并确认；未知执行结果仍仅查询原任务，不自动重放。成功重建生成新修订，已有历史修订与发布版本不覆盖。此流程不是全部边／面交互、Sketcher 约束或 PartDesign 历史编辑的替代品。

## 验证证据

真实 stdio MCP 读取当前 FreeCAD 1.1.4，返回 22 个工作台和 462 条当前注册命令，包含原生命令资源文本。之前的 606 条是另一轮工作台初始化后的发现记录，不能冒充当前进程清单。工作台初始化后，注册命令数量可能增加。

已验证大目录搜索、不丢弃未知命令、同源与账号限制、参数入口、工作台恢复失败、进程复用失效、迟到响应不覆盖新目录、未知结果只查回不重执行，以及桌面／窄屏白色布局和实际 WebGL 渲染。新增规格任务的隔离 Chrome 测试验证：当前主体尺寸／孔位置、参数确认、修订更新后的旧草稿禁用、圆角目录入口、钣金参数和未知执行结果禁写。图片和真实 MCP 目录读取收据在 `.runtime/catalog-ui-evidence/` 与 `.runtime/catalog-live-*/`，是运行产物，不提交到 Git。

本轮真实内核已启动并通过标准 stdio MCP 只读发现 462 条注册命令、22 个工作台。新增任务的完整实机验收未完成：对当前本地系统创建独立测试账号返回 409；使用新生成的服务配置提交独立队列作业返回 401，没有认领成功。没有使用现有账号、降低认证或重放未知作业，未修改任何现有 CAD 文档。保留的实机浏览器脚本现在仅允许隔离栈端口 18001，不能默认对业务库注册账号。不能用目录读取或隔离 HTTP 测试代替实际几何和登录链路的验收。

最新专项结果：82 项生产建模 Node 测试、18 项 Chrome 浏览器测试、55 项相关 Python 测试全部通过；13 类任务默认草稿均通过真实服务端 `validate_spec` 校验，前端生产构建成功（保留已有的大 bundle 提醒）。按测试驱动方式补充了位置／旋转缺失不能猜为原点、圆柱角度缺失不能猜为完整圆柱的回归用例。独立只读代码审查没有剩余阻断项；该结论只针对本次部分扩展，不提升全功能或实机覆盖状态。

Agent 全套回归为 2122 passed、72 failed、3 skipped；71 项在 [基线清单](freecad-document-baseline-failures.md) 中已复现，另有并行工作区的 `test_optional_cad_dispatch.py::test_explicit_engineering_query_is_not_skipped_without_following_repair_plan` 失败，异常来自 Runtime recovery 的任务身份检查。本轮没有修改该路径。完整输出在 `.runtime/freecad-workspace-current-agent-tests.log`；不宣称整个项目测试全通过。

原有已验证能力报告绑定适配器摘要。本次改变发现程序后，旧摘要证据不能自动提升为新版本全部验收通过；没有调用收费 AI，也不标记 AI 全功能已验证。
