# 维修方案页重复加载修复（2026-10-07）

用户反馈每次打开维修方案页面都需要重新刷新。实际原因是前端切换页面时卸载了维修方案组件，列表、选中项和删除标记全部重置；再次进入必须等待接口。加载函数还把方案与私有工单请求合并等待，慢工单会挡住已返回的方案。每五秒后台读取也重复显示“刷新中”。

只读检查实际后端：三次 GET 均首次正常返回已有方案，历史状态 ready，耗时分别为 1195、1078、1058 毫秒，返回内容相同。请求读取保存的方案和当前派发信息，不会重新执行诊断。

## 已修改

- 首次访问后，在当前应用会话内保留维修方案列表、删除标记和选中项。离开页面时卸载可视内容/图纸、取消请求并停止轮询；返回时立即展示已读内容，再后台读取最新状态。
- 方案与工单独立请求、独立更新、分别限制并发。慢工单不阻塞首次方案展示或后续方案轮询。
- 后台刷新不清空列表、不反复切换“刷新中”；刷新失败保留已读方案并提示错误。手动刷新按钮仍可使用。
- 私有工单按用户编号和角色隔离，切换身份的第一帧不显示旧关联，迟到的旧请求不能写回。删除标记继续过滤旧监控和工单快照。
- 修复方案先返回而监控快照仍为 null 时的页面崩溃。

仅修改前端读取和页面状态。本轮没有重新派工、写入业务数据、控制设备或重启后端。缓存只在当前应用内存中，不使用浏览器持久存储；完整重载网页仍需首次读取接口。
