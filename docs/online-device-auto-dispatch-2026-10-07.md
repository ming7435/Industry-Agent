# 按登录人员与故障设备自动派工

依据用户 2026-10-07 的新指令：先修改规则，查询当前登录人员及故障设备，派给对应人员。该规则取代之前仅因故障为 high/critical 就要求人工批准创建工单的规则；其他动作及明确要求审批的请求保留审批校验。

## 派工规则

1. 登录状态来自服务端未过期会话。账号必须启用、角色必须是维修人员，且 `primary_device_id` 必须等于工单设备。关闭网页并不等于退出登录；退出或会话过期后不再列为在线候选。
2. 同一设备若有多名合格人员，按在手工单量、用户编号确定顺序。不使用客户端自报的在线状态或负责人，也不回退给其他设备人员或监督员。
3. 派工写入前，后端再次核验人员资格。已派工工单重复请求原负责人保持幂等，不能隐式换人。
4. 诊断、维修必要性、方案、资料和库存校验通过后自动派工。设备启停和维修完成验收沿用原规则。
5. 暂无对应在线负责人时返回 `waiting_for_personnel`，保留待派工工单。明确重试先核对当前设备、报警与采样时间，再复用原工单和创建幂等键；重复重试不会新建工单。
6. 页面读取不触发派工。新故障按上述规则自动匹配；已经等待人员的工单在负责人登录后，通过现有“重新校验并派工”入口继续，本次没有新增后台轮询派工任务。

## 验证边界

回归测试使用临时数据库、隔离 HTTP 后端和模拟设备，不向实际设备注入故障、不写入现场工单、不调用付费模型。实际环境仅查询账号公开信息、会话有效性、设备状态和保存方案；不记录密码、会话令牌或令牌散列。

本次涉及团队会话查询、工单分配、Runtime 等待状态、保存方案重试及页面状态呈现。工作区既有的 CAD 和其他修改保持原样，不作为本次派工修改成果认领。
