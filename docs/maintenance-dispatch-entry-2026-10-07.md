# 维修方案页的派工入口

原页面对任何已关联工单直接禁用“重新校验并自动派工”，没有说明原因，也把已有但尚未分配的 open 工单一起禁用。从方案进入工单页时只切换页面，未指定工单，可能按当前设备报警选中了另一条记录。

已调整为：

- 已派发工单显示编号、负责人、状态和“进入工单处理”；跳转携带工单编号，并从当前账号可见工单列表选中对应记录。
- 未分配的 open 工单仍可重新校验续派，只发送原流程要求的命令编号。
- 关联工单未读出、读取失败、当前账号不可见或历史方案缺事件时显示具体提示。读取失败可重试读取，不把失败解释为没有派单。
- 检查工单保留检查范围；维修完成说明和复机申请仍在工单页提交。

验证：新入口浏览器用例 7 项、维修方案页面状态 7 项、检查流程 7 项、工单读取 8 项、简化完成流程 5 项全部通过；相关单元测试 43 项通过，生产构建成功。没有修改后端派工规则，也没有执行真实派工、维修确认或设备控制。

实际 8001 静态页面以拦截全部 API 的方式验证：当前未派方案按钮可用；已保存工单字段形状在独立模拟场景中可直接打开对应工单，填写说明后完成按钮可用。旧方案在真实数据中已被删除，模拟场景不恢复或修改真实删除标记。证据在 `.runtime/verification/maintenance-dispatch-entry-20261007/served-ui-result.json`。
