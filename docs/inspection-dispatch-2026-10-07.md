# 预警现场检查工单与自动派发

2026-10-07。修复有效预警因“不需要拆修”而不能生成检查工单，以及检查单被拆修 BOM 条件阻断的问题。

## 派发规则

- 对证据完整、置信度达标、设备和报警一致的有效预警，生成 `plan_kind=inspection` 的现场检查方案；保留 `maintenance_required=false`，单独设置 `inspection_required=true`。
- 检查使用固定的只读检查步骤，不调用维修方案生成、不预留备件，也不要求拆修 BOM。已有设备图纸继续作为参考资料展示。
- 普通维修继续经过原有 CAD、零件、证据和维修条件校验。低置信度、演示数据、明确只监控或不处理、已解除或设备不匹配的报警不能借检查路径派单。
- 后端根据真实有效登录会话及设备归属选择对应维修人员。没有该设备的在线负责人时保留等待，后续重试重新核验故障；重复派发沿用原工单。

## 检查结果与结束

- 检查人员通过“提交检查结果”提交记录。Agent 从已保存工单确定设备，读取 Factory 当前状态，将真实登录人员及服务端快照发给内部检查记录接口。
- Backend 校验被派工人员、角色、精确设备、工单状态、记录，以及当前快照的身份、报警、指标、互锁和时效。检查快照最多允许 5 分钟，不能使用客户端提供的核验结论。
- 核验通过后检查工单直接结束；仍有报警、数据过期或缺项时保存记录并保持处理中，页面展示具体原因。重复提交已结束检查单不会覆盖原核验事实。
- 允许清除预警后的安全停止状态结束检查，以免其他维修仍使整线停止时发生相互等待；检查结束本身不启动设备。尚未完成的检查单仍保留原整线限制。
- 检查结果使用独立的 `source=inspection`，不能提供维修确认、复机授权或成功维修学习记录。
