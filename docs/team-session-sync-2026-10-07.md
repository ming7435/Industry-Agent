# 登录显示与工单权限同步

## 实际原因

截图中的顶部显示 `lmy`，工单和催办接口却返回“请先登录”。只读检查确认账号正常，但当时 Redis 中没有有效维修会话；日志中工单接口先返回成功，随后持续返回 401。会话固定八小时到期，后端普通重启不会清除会话；现有证据不能确定这次是到期还是此前退出。

前端 `TeamAccess` 原先只在初次加载时查询身份。后续业务请求返回 401 时，顶部仍保留旧 actor，因此登录显示和实际权限长期不一致。隔离回放已证明 Monitor 双向传递 Cookie/Set-Cookie 正常，本次不调整后端登录机制。

## 修复范围

- 账号请求和工单请求共用会话失效通知。受保护请求返回 401 时立即清除旧身份、工单和催办视图，并提示重新登录；非 JSON 的 401 也有效。
- 显式重新登录建立新的会话版本，旧请求的成功或失败返回都不能覆盖新账号。同账号重新登录也隔离旧请求。
- 403 权限拒绝、503 暂时不可用、CAD 外部账号的 401 不退出维修账号。
- 重新登录后工单和催办重新读取；工单号、负责人和业务数据不变。
- 保留之前的方案复核门禁。原工单的数据回放已确认“重新生成并校验方案”入口可见，且不会误报没有对应报警工单。

旧标签页已经加载的 JavaScript 需要重新载入才能运行代码更新。页面无需在日常切换时反复刷新；有效登录过期仍需由用户重新输入账号密码。

验证使用真实 React 组件和生产构建，以及隔离的登录、工单数据接口；不读取用户浏览器凭据，不创建线上会话，不提交维修完成或控制设备。

最终 Node 回归 23/23、浏览器回归 34/34 通过，涵盖完整 App 的 7 项登录恢复场景。生产构建成功，8001 已提供 `index-xbK7qITs.js`。直接从 8001 加载该构建的隔离回放通过：原工单与复核按钮可见、没有“尚无对应报警工单”的错误提示、会话失效后顶部切回注册/登录并清除旧私有工单。浏览器无脚本异常、无业务写入。
