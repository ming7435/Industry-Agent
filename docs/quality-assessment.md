# 尺寸与视觉质检分类

## 用户要求

质检页同时提供尺寸和视觉检测；删除通用排查建议；展示问题位置、问题分类、设备参数或图纸等归因状态，以及清洗、返工、报废重造等处置方向；核实质检 Agent 的真实接入情况。

## 实现选择

沿用已认证的尺寸 API 和 PatchCore → YOLO 串联 API。在 QualityAgent 增加共用的证据分类能力，由两条真实接口调用。前端只展示服务器分类，不自行推断设备故障。尺寸记录保留原始批次，读取时重新分类；视觉分类随检测记录持久化。

按用户补充要求，保留“视觉检测”和“尺寸检测”两个独立页签，各自展示检测结果与问题分类。切换时隐藏另一页签，保持组件实例以保留图片、输入和结果；尺寸页不再重复展示视觉检测。两种检测分别标注来源：模拟尺寸批次、上传图片或公开参考图。设计版本相同不代表同一实物，不合并为整件合格或放行结论。

## 分类与处置

- 尺寸偏差：定位到参数和样本，设备参数、图纸、测量原因待确认；复测后判定。
- 数据缺失：补测后复检；未覆盖的设计参数单独计数。
- 污渍：清洗后复检；细丝：去除异物后复检。
- 表面损伤：返工评估；结构破损、缺料：报废重造评估。
- PatchCore 异常且 YOLO 无定位：隔离待复核。

所有处置保持未执行。工艺参数、公差、加工余量或设计审核证据不足时，不确认根因，不自动报废、修改图纸或控制设备。本次不更换模型权重，不恢复此前已取消的训练任务。

## 验证

规则测试覆盖缺测、未知类别、报废评估边界、模型定位失败、公开参考图及输入不变性；接口测试覆盖认证、检测、保存和重读；浏览器测试覆盖双检测展示、建议移除和窄屏布局。

## 补充要求：逐件联合判定与统计

用户进一步明确：需要合格率、不合格类型，以及合格／不合格后的处理方式；尺寸与视觉入口分开，但结果须组合。新增共享的“联合质检结果与处理”，按同一账号、尺寸请求、批次、设计版本及样本编号关联。用户选择图片对应样本后，PatchCore → YOLO 的完整结果保存到该样本；刷新页面可重读，复检更新同一样本，既不增加批次件数，也不将一图套用到全批次。

- 两项通过：合格，处理方向为保存记录、进入下一工序或入库。
- 任一项已发现不合格：不合格，先隔离；污渍清洗复检，细丝去除异物复检，表面损伤返工评估，结构缺损报废重造评估，尺寸偏差复测后判定返工或重造。多种问题同时保留。
- 无已知不合格但检测缺项、未关联图片或证据不可核验：待判定，补检。
- 合格率 = 合格件数 /（合格件数 + 不合格件数）；待判定单列。一件可有多种不合格类型，每种类型按涉及样本去重。

后端从已鉴权、已校验的尺寸批次和已保存视觉记录重新生成联合结果，不接受前端上传合格结论。参考测试图、生产实物登记与模拟批次禁止混用。新视觉记录写入失败时不得保留旧联合合格结论。联合判定对已知异常采取“失败优先”，因此已有异常但尚有缺测的样本会计为联合不合格；原始尺寸批次历史计数保持原样。

当前尺寸来自模拟比对仪，联合模块明确标注“模拟联合验证”，不声称真实产线良品率。清洗、返工、报废、入库及设备控制均未自动执行；设备参数或图纸根因仍需对应证据。模型权重和阈值未调整。

单项诊断统计另按来源保留：视觉只统计完整串联记录，子阶段不重复计数；同图复检另算图次；研究模型检出的异常仍计入分母，避免剔除异常后虚增合格率。此前 8 张真实公开图片的保存记录复核为 2 图次正常、6 图次异常（25%），模型类别为暗斑 4 图次／14 框、缺损 2 图次／2 框。这是模型判定统计，不代表定位准确率，且没有将这些公开图片伪装成模拟样本的实拍证据。

本轮验收：112 项后端测试、75 项前端与浏览器测试通过，生产构建通过。覆盖九种尺寸／视觉组合、账号／批次／设计／样本隔离、未知异常、证据写入失败、复检去重、刷新持久化与窄屏。浏览器端到端用受控检测数据验证同一样本的联合合格及多种不合格处置，截图中的 50% 为测试夹具数据。确认无活跃运行任务后更新本地平台；8001 页面及 8010/8020/8030/8040/8050 服务检查通过，新增接口未登录返回 401，实际未登录页面加载新版资源、两个入口切换无脚本错误。当前账号的已登录数据页面未自动接管。验收文件：`joint-backend-final.txt`、`joint-frontend-final.txt`、`joint-build.txt`、`joint-live.json`，均在 `output/quality-classification-20261026/`。

## 2026-10-26：从质检工作台移除模拟批次

按最新要求，正常质检页面不再调用 `/api/quality/simulation/*`，不再生成十件假测量值，也不再展示模拟工位、模拟联合验证或历史流程验证入口。既有模拟历史未删除或改写为真实记录。尺寸、视觉两个页签和逐件联合判定保留。

新增 `GET/POST /api/quality/vision/batches` 与 `GET /api/quality/vision/batches/{request_id}`，使用原有账号鉴权和同源写入保护。导入 UTF-8 CSV，记录真实批次号、零件编号、图纸版本、检验项目、验收上下限、实测值与单位、测量时间及标准来源；空白模板不含任何预填测量值。检验清单完整性由提交人员明确声明，未声明时不能判定整件尺寸通过。与当前上传图片无法关联的单图检查不计入批次合格率。

尺寸比较使用十进制验收范围，边界包含在内；不把 CAD 名义值当公差、不从几何模型生成测量值。缺测、缺少上下限、单位不符或检验清单未确认完整时保持待判定；已明确超差优先判为不合格。相同文件重复导入幂等，复检文件生成新的不可变测量版本，同批次列表仅显示最新版本。图片绑定账号、批次、测量版本、图纸及物理零件；尺寸版本变更或视觉复检失败会使旧视觉通过结果失效，避免旧合格结论继续生效。原始导入记录保留并按内容摘要核验，未自动执行入库、设备调整或报废。

文件查找核对了项目数据目录、下载文件夹及桌面相关工业数据目录，发现的齿轮图片清单来源于公开 MANTA 数据集；CAD 文件和虚拟工厂文件不属于实际测量记录。后台 `production_part` 表读取结果为 0 条，未找到可证明属于当前批次的尺寸记录、验收标准与对应图片组合。因此没有向正式账号导入测试数据，也没有宣称完成当前批次真实验收。

验证：102 项后端/API/代理测试通过；55 项前端及浏览器检查通过；生产构建通过。浏览器用受控记录验证真实导入接口交互、相同零件双检关联、超差/缺测处理、刷新持久化、禁止自动模拟、未登录隔离及移动端布局。旧浏览器用例中“CAD 发布自动刷新模拟标准”和“自动生成模拟批次”的预期已由“导入实测记录、保持测量版本、禁止读取模拟源”的用例替换；模拟后端历史完整性测试仍保留并通过。
