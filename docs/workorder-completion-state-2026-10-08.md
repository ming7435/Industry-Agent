# 维修确认后仍显示处理中

## 原因

运行中的 Agent 未设置 `FACTORY_CONTROL_MODE=virtual`。`LineController.confirm_and_restart` 在读取工单和保存维修确认前就返回控制拒绝，响应只有 `machine_control`，没有工单。接口返回 HTTP 200，前端将其当作成功，既没更新原工单，也没有展示拒绝原因。

现场只读检查显示，`WO-B1BAE75E20` 仍是 `in_progress`，此前单独保存的处理说明是“完成”。确认时间和确认人为空。该设备当前的真实快照通过预启动检查。

## 修改

- 将自动设备控制开关与人工维修确认分开。本人填写真实反馈、设备恢复数据通过检查后，Backend 保存维修确认及凭据，工单变为 `completed`。即使自动控制关闭，也会返回完整的对应工单。
- 自动控制关闭时只读取设备数据，不调用停止或启动接口，不启用控制模式；复机结果明确为“自动复机控制未启用”。关闭工单仍需要启动后复核。
- 控制开启时保留整线停机对账、其他未完成故障检查、真实设备预启动检查和启动后复核。
- 设备检查未通过时保留真实工单状态，并展示报警、互锁、指标或数据时间等具体原因。
- 前端验证动作回包的工单编号、设备及负责人。缺失或不匹配的回包不再被视为成功，错误提示不会被列表轮询清除。
- 页面分别显示“维修已完成，复机申请未通过”和“维修确认未通过”；完整状态同步到维修方案列表，后续轮询保留本次复机结果。
